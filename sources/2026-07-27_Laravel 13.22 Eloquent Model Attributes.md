# Laravel 13.22 기준 Eloquent Model Attribute 총정리

> **문서 기준**
> - `laravel/framework` `13.x` 브랜치 (`Illuminate\Foundation\Application::VERSION === '13.22.0'`)
> - 대상 네임스페이스: `Illuminate\Database\Eloquent\Attributes\*` (총 **24개**)
> - "도입 버전"은 해당 attribute 클래스 파일이 최초로 추가된 커밋을 찾고, 그 커밋을 포함하는 가장 빠른 릴리스 태그를 기준으로 산출했습니다.
> - 본문의 동작 설명은 블로그가 아니라 실제 프레임워크 소스(`Model.php`, `Concerns/*.php`, `Auth/Access/Gate.php` 등)를 읽고 정리한 것입니다.

## 1. 큰 그림 — 왜 attribute인가

Laravel은 10.44(2024-02)에 `#[ObservedBy]` / `#[ScopedBy]`를 도입한 이후, 모델의 **설정(configuration)** 을 protected 프로퍼티나 메서드 오버라이드 대신 **클래스 선언부의 PHP native attribute** 로 표현하는 방향을 꾸준히 확장해 왔습니다. Laravel 13에서 이 흐름이 한 번에 크게 늘어났습니다.

핵심적으로 이해해야 할 점 세 가지입니다.

1. **동작을 바꾸는 기능이 아니라 "설정을 어디에 쓰느냐"의 문제입니다.** `#[Fillable(['name'])]`과 `protected $fillable = ['name'];`은 동일한 결과를 만듭니다.
2. **모두 하위 호환입니다.** 기존 프로퍼티/메서드 방식은 전혀 deprecated 되지 않았고, attribute를 아예 안 써도 됩니다.
3. **대부분의 경우 "명시적으로 선언한 프로퍼티가 우선"입니다.** 뒤에서 자세히 다루지만, attribute는 대체로 프로퍼티가 기본값일 때만 적용되거나 프로퍼티 값과 병합됩니다. 다만 `#[Table(name:)]` 등 일부는 규칙이 다르므로 개별 확인이 필요합니다.

시간순 흐름:

```
v10.44.0 (2024-02)  ObservedBy, ScopedBy
v11.28.0 (2024-10)  CollectedBy
v11.39.0 (2025-01)  UseFactory
v12.4.0  (2025-03)  Scope                     ← 메서드 레벨
v12.18.0 (2025-06)  UsePolicy
v12.19.0 (2025-06)  UseEloquentBuilder
v12.22.0 (2025-08)  Boot, Initialize          ← 메서드 레벨 (주로 trait용)
v12.29.0 (2025-09)  UseResource, UseResourceCollection
v13.0.0  (2026-02)  Appends, Connection, Fillable, Guarded, Hidden,
                    Table, Touches, Unguarded, Visible   ← 대량 추가
v13.2.0  (2026-03)  DateFormat, WithoutIncrementing, WithoutTimestamps
v13.21.0 (2026-07)  RouteKey
```

> 참고: 앞선 대화에서 `#[RouteKey]`를 "13.2"로 알고 계셨는데, 실제로는 **13.21.0**입니다. 13.2.0에 들어간 것은 `#[DateFormat]`, `#[WithoutIncrementing]`, `#[WithoutTimestamps]`입니다. 버전 표기가 헷갈리기 쉬운 구간입니다.

## 3. 테이블 / 스키마 정의

### 3.1 `#[Table]` — 가장 많은 것을 대체하는 attribute

```php
#[Attribute(Attribute::TARGET_CLASS)]
class Table
{
    public function __construct(
        public ?string $name = null,
        public ?string $key = null,          // primaryKey
        public ?string $keyType = null,      // 'int' | 'string'
        public ?bool $incrementing = null,
        public ?bool $timestamps = null,
        public ?string $dateFormat = null,
    ) {}
}
```

**Before**

```php
class LegacyUser extends Model
{
    protected $table = 'tb_user_master';
    protected $primaryKey = 'user_no';
    protected $keyType = 'string';
    public $incrementing = false;
    public $timestamps = false;
    protected $dateFormat = 'Y-m-d H:i:s';
}
```

**After**

```php
use Illuminate\Database\Eloquent\Attributes\Table;
use Illuminate\Database\Eloquent\Model;

#[Table(
    name: 'tb_user_master',
    key: 'user_no',
    keyType: 'string',
    incrementing: false,
    timestamps: false,
    dateFormat: 'Y-m-d H:i:s',
)]
class LegacyUser extends Model
{
    // ...
}
```

레거시 DB 스키마를 다룰 때(컬럼/테이블 네이밍이 Laravel 규칙과 다른 경우) 프로퍼티 6개가 클래스 상단 한 블록으로 정리되는 효과가 있습니다. 20년 된 미디어 시스템 같은 곳의 모델 클래스를 생각하면 체감이 클 수 있는 부분입니다.

#### 내부 동작 (`Model::initializeModelAttributes()`)

```php
public function initializeModelAttributes()
{
    $table = static::resolveClassAttribute(Table::class);

    $reflection = new ReflectionClass(static::class);

    $declaresTable = $reflection->hasProperty('table')
        && $reflection->getProperty('table')->getDeclaringClass()->getName() === static::class;

    if (! $declaresTable && $reflection->getAttributes(Table::class) !== []) {
        $this->table = $table->name ?? null;      // attribute가 이김
    } else {
        $this->table ??= $table->name ?? null;    // 프로퍼티가 이김
    }

    $this->connection ??= static::resolveClassAttribute(Connection::class, 'name');

    if ($this->primaryKey === 'id' && $table && $table->key !== null) {
        $this->primaryKey = $table->key;
    }

    if ($this->keyType === 'int' && $table && $table->keyType !== null) {
        $this->keyType = $table->keyType;
    }

    if (static::resolveClassAttribute(WithoutIncrementing::class) !== null) {
        $this->incrementing = false;
    } elseif ($table && $table->incrementing !== null) {
        $this->incrementing = $table->incrementing;
    }
}
```

이 메서드는 `Model::__construct()`에서 `initializeTraits()` 직후에 호출됩니다.

```php
public function __construct(array $attributes = [])
{
    $this->bootIfNotBooted();
    $this->initializeTraits();
    $this->initializeModelAttributes();   // ← 여기
    $this->syncOriginal();
    $this->fill($attributes);
}
```

#### 반드시 알아둘 우선순위 규칙

| 항목 | 규칙 |
|---|---|
| `table` | **해당 클래스가 직접 `$table` 프로퍼티를 선언하지 않았고** attribute가 있으면 attribute가 값을 덮어씀. (상속받은 `$table` 값도 덮어씀) |
| `primaryKey` | `$this->primaryKey`가 기본값 `'id'`일 때만 attribute 적용 |
| `keyType` | `$this->keyType`이 기본값 `'int'`일 때만 attribute 적용 |
| `incrementing` | `#[WithoutIncrementing]` > `#[Table(incrementing:)]` |
| `timestamps` | `$this->timestamps === true`(기본값)일 때만, 그리고 `#[WithoutTimestamps]` > `#[Table(timestamps:)]` |
| `dateFormat` | `$this->dateFormat`이 `null`일 때만, `#[DateFormat]` > `#[Table(dateFormat:)]` |

즉 **프로퍼티를 명시적으로 기본값과 다르게 써 두면 attribute는 무시됩니다.** 두 방식을 한 클래스에 섞으면 "attribute를 고쳤는데 왜 안 바뀌지?" 하는 상황이 생길 수 있으니, 모델 단위로 한 가지 스타일을 정해 두는 편이 안전합니다.

> `primaryKey`를 `'id'`로, `keyType`을 `'int'`로 **명시적으로 다시 써 놓은** 모델이라면 값이 기본값과 같으므로 attribute가 적용됩니다. 사람이 보기엔 "명시했는데?" 싶지만 프레임워크는 값만 비교합니다.

### 3.2 `#[Connection]`

```php
#[Attribute(Attribute::TARGET_CLASS)]
class Connection
{
    public function __construct(public UnitEnum|string $name) {}
}
```

```php
use Illuminate\Database\Eloquent\Attributes\Connection;

#[Connection('reporting')]
class DailyStat extends Model
{
    // ...
}
```

문자열뿐 아니라 **enum**도 받습니다. `Model::getConnectionName()`이 `enum_value()`를 통과시키기 때문입니다.

```php
enum DbConnection: string
{
    case Primary = 'mysql';
    case Reporting = 'reporting';
    case Archive = 'archive';
}

#[Connection(DbConnection::Reporting)]
class DailyStat extends Model
{
    // ...
}
```

읽기 전용 리플리카나 레거시 DB를 별도 커넥션으로 두는 구조에서 커넥션 이름을 문자열로 흩뿌리는 대신 enum으로 모을 수 있습니다.

적용 조건: `$this->connection ??= ...` 이므로 **프로퍼티가 `null`일 때만** 적용됩니다.

### 3.3 `#[WithoutIncrementing]`

```php
#[Attribute(Attribute::TARGET_CLASS)]
class WithoutIncrementing {}
```

인자가 없는 마커(marker) attribute입니다.

```php
use Illuminate\Database\Eloquent\Attributes\Table;
use Illuminate\Database\Eloquent\Attributes\WithoutIncrementing;

#[Table(key: 'uuid', keyType: 'string')]
#[WithoutIncrementing]
class Order extends Model
{
    // public $incrementing = false; 와 동일
}
```

`#[Table(incrementing: false)]`보다 의도가 눈에 잘 들어오고, UUID/ULID 기본키 모델에서 자주 쓰이게 될 조합입니다.

### 3.4 `#[WithoutTimestamps]`

```php
#[Attribute(Attribute::TARGET_CLASS)]
class WithoutTimestamps {}
```

```php
use Illuminate\Database\Eloquent\Attributes\WithoutTimestamps;

#[WithoutTimestamps]
class AuditLog extends Model
{
    // public $timestamps = false; 와 동일
}
```

**이름이 비슷한 다른 기능과 헷갈리기 쉬움**

- `Illuminate\Database\Eloquent\Attributes\WithoutTimestamps` → 모델 전체에 대해 타임스탬프 영구 비활성화
- `Model::withoutTimestamps(fn () => ...)` → 클로저 실행 동안만 일시적으로 비활성화

두 개는 완전히 별개입니다. `use` 문에서 자동 임포트할 때 잘못 잡히지 않는지 확인하는 게 좋습니다.

적용 조건 (`HasTimestamps::initializeHasTimestamps()`):

```php
#[Initialize]
public function initializeHasTimestamps()
{
    if ($this->timestamps === true) {
        if (static::resolveClassAttribute(WithoutTimestamps::class) !== null) {
            $this->timestamps = false;
        } elseif (($table = static::resolveClassAttribute(Table::class)) && $table->timestamps !== null) {
            $this->timestamps = $table->timestamps;
        }
    }
}
```

### 3.5 `#[DateFormat]`

```php
#[Attribute(Attribute::TARGET_CLASS)]
class DateFormat
{
    public function __construct(public string $format) {}
}
```

```php
use Illuminate\Database\Eloquent\Attributes\DateFormat;

#[DateFormat('Y-m-d H:i:s')]
class LegacyArticle extends Model
{
    // protected $dateFormat = 'Y-m-d H:i:s'; 와 동일
}
```

MySQL이 아니라 오래된 스키마에서 `datetime`을 문자열로 저장하는 경우처럼, 기본 포맷과 다른 저장 포맷을 쓸 때 사용합니다.

`HasAttributes::initializeHasAttributes()`에서 다음 순서로 결정됩니다.

```php
$this->dateFormat ??= static::resolveClassAttribute(DateFormat::class, 'format')
    ?? static::resolveClassAttribute(Table::class)->dateFormat
    ?? null;
```

## 4. Mass Assignment (대량 할당)

### 4.1 `#[Fillable]`

```php
#[Attribute(Attribute::TARGET_CLASS)]
class Fillable
{
    public array $columns;

    public function __construct(array|string ...$columns)
    {
        $this->columns = is_array($columns[0]) ? $columns[0] : $columns;
    }
}
```

**가변 인자(variadic)** 이므로 두 가지 문법 모두 됩니다.

```php
use Illuminate\Database\Eloquent\Attributes\Fillable;

#[Fillable(['title', 'body', 'published_at'])]   // 배열
class Post extends Model {}

#[Fillable('title', 'body', 'published_at')]     // 나열
class Post extends Model {}
```

`#[Fillable]`, `#[Guarded]`, `#[Hidden]`, `#[Visible]`, `#[Appends]`, `#[Touches]` 6개가 모두 같은 가변 인자 패턴입니다.

**병합 동작**: `$fillable` 프로퍼티와 **덮어쓰기가 아니라 병합**됩니다.

```php
public function mergeFillable(array $fillable)
{
    if ($fillable === []) {
        return $this;
    }

    $this->fillable = array_values(array_unique(array_merge($this->fillable, $fillable)));

    return $this;
}
```

따라서 부모 클래스에 `protected $fillable = ['id']`가 있고 자식에 `#[Fillable(['title'])]`이 있으면 결과는 `['id', 'title']`입니다. 이 병합 동작은 상속 구조에서 의도치 않게 화이트리스트가 넓어질 수 있으므로, 보안에 민감한 모델이라면 한 번 확인해 볼 만합니다.

### 4.2 `#[Guarded]` / `#[Unguarded]`

```php
use Illuminate\Database\Eloquent\Attributes\Guarded;
use Illuminate\Database\Eloquent\Attributes\Unguarded;

#[Guarded(['id', 'is_admin'])]
class User extends Model {}

#[Unguarded]              // protected $guarded = []; 와 동일
class ImportStaging extends Model {}
```

```php
#[Initialize]
public function initializeGuardsAttributes()
{
    $this->mergeFillable(static::resolveClassAttribute(Fillable::class, 'columns') ?? []);

    if ($this->guarded === ['*']) {                                       // 기본값일 때만
        if (static::resolveClassAttribute(Unguarded::class) !== null) {
            $this->guarded = [];                                          // Unguarded 우선
        } else {
            $this->guarded = static::resolveClassAttribute(Guarded::class, 'columns') ?? ['*'];
        }
    }
}
```

- `$guarded`가 기본값 `['*']`일 때만 attribute가 적용됩니다.
- `#[Unguarded]`가 `#[Guarded]`보다 우선합니다. (둘 다 붙이면 `#[Guarded]`는 무시)
- `#[Unguarded]`는 대량 할당 방어를 끄는 것이므로, 외부 입력이 직접 닿는 모델에는 쓰지 않는 편이 안전합니다. 시딩/임포트 전용 모델 정도로 한정하는 게 무난합니다.

## 5. 직렬화 (Serialization)

### 5.1 `#[Hidden]` / `#[Visible]`

```php
use Illuminate\Database\Eloquent\Attributes\Hidden;
use Illuminate\Database\Eloquent\Attributes\Visible;

#[Hidden(['password', 'remember_token'])]
class User extends Model {}

#[Visible(['id', 'name', 'created_at'])]
class PublicProfile extends Model {}
```

```php
#[Initialize]
public function initializeHidesAttributes()
{
    $this->mergeHidden(static::resolveClassAttribute(Hidden::class, 'columns') ?? []);
    $this->mergeVisible(static::resolveClassAttribute(Visible::class, 'columns') ?? []);
}
```

역시 프로퍼티와 **병합**입니다.

### 5.2 `#[Appends]`

```php
use Illuminate\Database\Eloquent\Attributes\Appends;

#[Appends(['full_name', 'is_admin'])]
class User extends Model
{
    protected function fullName(): Attribute
    {
        return Attribute::get(fn () => "{$this->first_name} {$this->last_name}");
    }
}
```

접근자(accessor) 결과를 `toArray()` / `toJson()` 출력에 항상 포함시킵니다. `HasAttributes::initializeHasAttributes()`에서 `mergeAppends()`로 병합됩니다.

> 여기서 이름이 두 겹으로 겹칩니다. `Illuminate\Database\Eloquent\Casts\Attribute`(접근자/변경자 정의용)와 `Illuminate\Database\Eloquent\Attributes\*`(PHP attribute)는 서로 다른 것입니다. 한 파일에서 둘 다 쓸 때 `use ... as`로 별칭을 주면 읽기 편합니다.

## 6. 관계 / 이벤트 / 스코프

### 6.1 `#[Touches]`

```php
use Illuminate\Database\Eloquent\Attributes\Touches;

#[Touches(['post', 'author'])]
class Comment extends Model
{
    public function post(): BelongsTo { /* ... */ }
    public function author(): BelongsTo { /* ... */ }
```


### 6.2 `#[ObservedBy]` (10.44 도입)

```php
#[Attribute(Attribute::TARGET_CLASS | Attribute::IS_REPEATABLE)]
class ObservedBy
{
    public function __construct(public array|string $classes) {}
}
```


**`IS_REPEATABLE`** 이므로 여러 번 붙일 수 있고, 배열로 여러 개를 한 번에 줄 수도 있습니다.

**상속 병합 동작** — 여기가 다른 attribute와 결정적으로 다릅니다.

```php
public static function resolveObserveAttributes()
{
    $reflectionClass = new ReflectionClass(static::class);

    $isEloquentGrandchild = is_subclass_of(static::class, Model::class)
        && get_parent_class(static::class) !== Model::class;

    return (new Collection($reflectionClass->getAttributes(ObservedBy::class)))
        ->map(fn ($attribute) => $attribute->getArguments())
        ->flatten()
        ->when($isEloquentGrandchild, function (Collection $attributes) {
            return (new Collection(get_parent_class(static::class)::resolveObserveAttributes()))
                ->merge($attributes);
        })
        ->all();
}
```

즉 `Model`을 바로 상속한 게 아니라 **중간 부모가 있는 경우(grandchild)**, 부모 체인의 옵저버를 전부 **누적**합니다. 뒤에서 설명할 `resolveClassAttribute()`(첫 번째 발견 하나만 사용)와 정반대 동작입니다.

### 6.3 `#[ScopedBy]` (10.44 도입)

```php
use Illuminate\Database\Eloquent\Attributes\ScopedBy;

#[ScopedBy(PublishedScope::class)]
#[ScopedBy([TenantScope::class, SoftDeleteAwareScope::class])]
class Post extends Model {}
```

`ObservedBy`와 거의 같지만 두 가지가 더 있습니다.

```php
$attributes = new Collection(
    $reflectionClass->getAttributes(ScopedBy::class, ReflectionAttribute::IS_INSTANCEOF)
);

foreach ($reflectionClass->getTraits() as $trait) {
    $attributes->push(...$trait->getAttributes(ScopedBy::class, ReflectionAttribute::IS_INSTANCEOF));
}
```

1. **trait에 붙은 `#[ScopedBy]`도 수집**합니다. 멀티테넌시 trait에 스코프를 같이 묶어 두는 패턴이 가능합니다.
2. **`IS_INSTANCEOF`** 로 조회하므로 `ScopedBy`를 상속한 커스텀 attribute를 만들어 쓸 수 있습니다.

```php
#[Attribute(Attribute::TARGET_CLASS | Attribute::IS_REPEATABLE)]

{
    public function __construct()
    {
        parent::__construct(TenantScope::class);
    }
}

#[TenantScoped]
class Invoice extends Model {}
```

DDD 스타일로 Bounded Context마다 공통 스코프를 강제하고 싶을 때 쓸 만한 확장 지점입니다.

```php
protected function guessResource(): JsonResource
{
    $resourceClass = $this->resolveResourceFromAttribute(static::class);

    if ($resourceClass !== null && class_exists($resourceClass)) {
        return $resourceClass::make($this);
    }

    foreach (static::guessResourceName() as $resourceClass) {
        if (is_string($resourceClass) && class_exists($resourceClass)) {
            return $resourceClass::make($this);
        }
    }

    throw new LogicException(sprintf('Failed to find resource class for model [%s].', get_class($this)));
}
```

## 9. 메서드 레벨 attribute

### 9.1 `#[Scope]` (12.4 도입)

```php
#[Attribute(Attribute::TARGET_METHOD)]
class Scope
{
    public function __construct() {}
}
```

**Before**

```php
class Post extends Model
{
    public function scopePublished(Builder $query): void
    {
        $query->whereNotNull('published_at');
    }
}

Post::published()->get();
```

**After**

```php
use Illuminate\Database\Eloquent\Attributes\Scope;

class Post extends Model
{
    #[Scope]
    protected function published(Builder $query): void
    {
        $query->whereNotNull('published_at');
    }
}

Post::published()->get();   // 호출 방식은 동일
```

`scope` 접두사 네이밍 규칙에서 벗어날 수 있고, 메서드 이름이 곧 스코프 이름이 됩니다.

```php
public function hasNamedScope($scope)
{
    return method_exists($this, 'scope'.ucfirst($scope)) || static::isScopeMethodWithAttribute($scope);
}

protected static function isScopeMethodWithAttribute(string $method)
{
    if (method_exists(static::class, $method)) {
        $reflectionClass = new ReflectionMethod(static::class, $method);

        return ! $reflectionClass->isPrivate() && $reflectionClass->getAttributes(LocalScope::class) !== [];
    }

    return false;
}
```

주의: **`private` 메서드에는 적용되지 않습니다.** `protected` 또는 `public`이어야 합니다.

`__callStatic`에서도 처리되므로 `Post::published()` 형태의 정적 호출이 그대로 동작합니다.

```php
public static function __callStatic($method, $parameters)
{
    if (static::isScopeMethodWithAttribute($method)) {
        return static::query()->$method(...$parameters);
    }

    return (new static)->$method(...$parameters);
}
```

### 9.2 `#[Boot]` / `#[Initialize]` (12.22 도입)

둘 다 인자가 없는 마커이며, 주로 **trait**에서 씁니다.

**Before** — trait 이름과 메서드 이름을 맞춰야 했습니다.

```php
trait HasTenant
{
    public static function bootHasTenant(): void { /* ... */ }
    public function initializeHasTenant(): void { /* ... */ }
}
```

trait 이름을 바꾸면 메서드 이름도 같이 바꿔야 하고, 안 바꾸면 조용히 호출되지 않는 함정이 있었습니다.

**After**

```php
use Illuminate\Database\Eloquent\Attributes\Boot;
use Illuminate\Database\Eloquent\Attributes\Initialize;

trait HasTenant
{
    #[Boot]
    public static function bootTenantScope(): void
    {
        static::addGlobalScope(new TenantScope);
    }

    #[Initialize]
    public function setUpTenantDefaults(): void
    {
        $this->mergeFillable(['tenant_id']);
    }
}
```

내부 동작 (`Model::bootTraits()`):

```php
foreach ((new ReflectionClass($class))->getMethods() as $method) {
    if (! in_array($method->getName(), $booted) &&
        $method->isStatic() &&
        (in_array($method->getName(), $conventionalBootMethods) ||
        $method->getAttributes(Boot::class) !== [])) {
        $method->invoke(null);

        $booted[] = $method->getName();
    }

    if (in_array($method->getName(), $conventionalInitMethods) ||
        $method->getAttributes(Initialize::class) !== []) {
        static::$traitInitializers[$class][] = $method->getName();
    }
}
```

- `#[Boot]`: **static 메서드**여야 하며, 모델 클래스당 한 번 부팅 시 호출
- `#[Initialize]`: 인스턴스 메서드, **모델을 `new` 할 때마다** 호출
- 기존 네이밍 규칙(`bootXxx` / `initializeXxx`)과 **병행 동작**하며 중복 호출은 방지됩니다

프레임워크 내부에서도 이미 이 방식을 씁니다. `GuardsAttributes::initializeGuardsAttributes()`, `HidesAttributes::initializeHidesAttributes()`, `HasTimestamps::initializeHasTimestamps()` 등에 `#[Initialize]`가 붙어 있습니다.

## 10. 공통 내부 동작 — `resolveClassAttribute()`

Laravel 13의 클래스 레벨 모델 attribute 대부분이 이 헬퍼 하나를 통과합니다.

```php
protected static function resolveClassAttribute(string $attributeClass, ?string $property = null, ?string $class = null)
{
    $class ??= static::class;

    $cacheKey = $class.'@'.$attributeClass.'@'.$property;

    if (array_key_exists($cacheKey, static::$classAttributes)) {
        return static::$classAttributes[$cacheKey];
    }

    try {
        $reflection = new ReflectionClass($class);

        do {
            $attributes = $reflection->getAttributes($attributeClass);

            if (count($attributes) > 0) {
                $instance = $attributes[0]->newInstance();

                return static::$classAttributes[$cacheKey] = $property ? $instance->{$property} : $instance;
            }

            foreach ($reflection->getTraits() as $trait) {
                $attributes = $trait->getAttributes($attributeClass);

                if (count($attributes) > 0) {
                    $instance = $attributes[0]->newInstance();

                    return static::$classAttributes[$cacheKey] = $property ? $instance->{$property} : $instance;
                }
            }
        } while ($reflection = $reflection->getParentClass());
    } catch (Exception) {
        //
    }

    return static::$classAttributes[$cacheKey] = null;
}
```

읽어야 할 포인트 다섯 가지:

1. **탐색 순서**: 자기 클래스 → 자기 클래스의 trait들 → 부모 클래스 → 부모의 trait들 → ... 최상위까지.
2. **첫 번째 발견 하나만 사용** (`$attributes[0]`). 상속 체인에서 여러 개가 있으면 가장 가까운 것이 이깁니다. `ObservedBy`/`ScopedBy`의 누적 병합과는 다릅니다.
3. **정적 캐싱**: `static::$classAttributes`에 `클래스@attribute@프로퍼티` 키로 캐시됩니다. 런타임 중 리플렉션이 반복되지 않아 비용은 사실상 첫 회에만 발생합니다. 다만 이 캐시는 **프로세스 수명 동안 유지**되므로, Octane(FrankenPHP/Swoole)처럼 워커가 오래 사는 환경에서도 문제가 없는 대신 런타임에 동적으로 바꿀 여지도 없습니다.
4. **예외를 삼킵니다** (`catch (Exception) {}`). 리플렉션 실패 시 조용히 `null`이 되므로, 동작하지 않을 때 예외로 알려주지 않습니다. attribute 클래스명 오타 등은 스스로 확인해야 합니다.
5. **`$property` 인자**: `resolveClassAttribute(RouteKey::class, 'key')`처럼 attribute 인스턴스 대신 특정 프로퍼티 값만 바로 꺼낼 수 있습니다.

### trait 지원 여부 정리

동일하게 "attribute"라고 불리지만 trait 탐색 지원이 제각각입니다.

| 해석 경로 | trait 탐색 | 상속 처리 |
|---|---|---|
| `resolveClassAttribute()` (Table, Connection, Fillable, RouteKey 등 대부분) | O | 첫 번째 발견 하나 |
| `ScopedBy` | O | 부모 체인 누적 병합 |
| `ObservedBy` | X | 부모 체인 누적 병합 |
| `CollectedBy` | X | 부모 체인, 첫 번째 발견 |
| `UseEloquentBuilder`, `UseFactory`, `UsePolicy`, `UseResource(Collection)` | X | 해당 클래스만 (`getAttributes()` 단발 호출) |

`UseEloquentBuilder`, `UseFactory`, `UsePolicy`, `UseResource` 계열은 **상속 체인을 훑지 않습니다.** 부모 모델에 붙여 두고 자식이 물려받기를 기대하면 동작하지 않으니, 상속 구조를 쓴다면 각 구체 클래스에 붙여야 합니다.

### 11.2 프로퍼티 방식과의 1:1 대조

```php
// ── 프로퍼티 방식 ────────────────────────────────

    protected $visible = [];
    protected $appends = ['excerpt'];
    protected $touches = ['author'];

    public function newEloquentBuilder($query) { return new PostBuilder($query); }

// ── attribute 방식 ──────────────────────────────
#[Connection('mysql')]
#[Table(name: 'posts', key: 'post_id', keyType: 'string', incrementing: false,
        timestamps: false, dateFormat: 'Y-m-d H:i:s')]
#[Fillable(['title', 'body'])]
#[Hidden(['secret'])]
#[Appends(['excerpt'])]
#[Touches(['author'])]
#[RouteKey('slug')]
#[CollectedBy(PostCollection::class)]
#[UseEloquentBuilder(PostBuilder::class)]
#[UseFactory(PostFactory::class)]
#[ScopedBy(PublishedScope::class)]
#[ObservedBy(PostObserver::class)]
class Post extends Model
{
    #[Scope]
    protected function published(Builder $q): void
    {
        $q->whereNotNull('published_at');
    }
}
```

## 12. 주의사항과 흔한 오해

### 12.1 존재하지 않는 attribute

일부 블로그 글에 `#[PrimaryKey]`, `#[KeyType]` 같은 attribute가 등장하는데, **13.22 소스에는 없습니다.** 프리릴리스 시점의 추측성 글로 보입니다. 기본키 관련 설정은 `#[Table(key: ..., keyType: ...)]`로 합니다. 13.22 기준 실제 존재하는 24개는 이 문서 2장 표가 전부입니다. 확인이 필요하면 프로젝트에서 직접 확인하는 게 가장 확실합니다.

```bash
ls vendor/laravel/framework/src/Illuminate/Database/Eloquent/Attributes/
```

### 12.2 프로퍼티와 섞어 쓰면 헷갈립니다

앞서 반복해서 나왔듯 각 attribute마다 적용 조건이 조금씩 다릅니다.

- 병합형: `Fillable`, `Hidden`, `Visible`, `Appends`
- 기본값일 때만 적용: `Guarded`, `Touches`, `primaryKey`, `keyType`, `timestamps`, `dateFormat`, `connection`
- attribute가 이기는 경우: `Table(name:)` (해당 클래스가 `$table`을 직접 선언하지 않은 경우)

이 차이를 매번 기억하기보다는 **모델 하나에서는 한 가지 스타일만** 쓰는 편이 실무적으로 안전합니다. 팀 컨벤션으로 정해 두는 게 좋습니다.

### 12.3 상속 규칙이 attribute마다 다릅니다

10장 표를 다시 확인해 주세요. 특히 `UseFactory` / `UsePolicy` / `UseEloquentBuilder` / `UseResource`는 상속 탐색을 하지 않으므로, 추상 베이스 모델에 붙여 두는 설계는 동작하지 않습니다.

### 12.4 정적 분석 / IDE

`#[Fillable(['title'])]`은 IDE 입장에서 그냥 상수 배열이라 `$fillable` 프로퍼티만큼의 정보를 주지 못할 수 있습니다. Larastan/PHPStan, IDE Helper 등의 도구가 attribute 방식을 어디까지 이해하는지는 도구 버전에 따라 다르므로, 대규모 전환 전에 CI에서 정적 분석이 그대로 통과하는지 먼저 확인해 보시는 게 좋겠습니다.

### 12.5 성능

리플렉션 비용을 걱정할 수 있지만 `resolveClassAttribute()`는 static 배열에 캐싱하므로 클래스·attribute 조합당 한 번만 발생합니다. `ObservedBy`/`ScopedBy` 계열은 부팅 시 한 번 해석됩니다. 실무에서 문제가 될 수준은 아닌 구조입니다.

### 12.6 도입 판단

이 변경들은 전부 "이미 되던 것을 다르게 쓰는 방법"입니다. `#[RouteKey]` PR(#60841)의 코멘트에서도 이런 종류의 추가가 정말 필요한지 의문을 제기한 의견이 있었고, 그 지적 자체는 합리적인 면이 있습니다. 정리하면 대략 이런 판단 기준이 됩니다.

**attribute가 유리한 경우**
- 레거시 스키마 대응으로 프로퍼티가 5~6개씩 붙는 모델
- trait로 공통 설정을 배포할 때 (`#[ScopedBy]` trait 지원, `#[Boot]`/`#[Initialize]`의 네이밍 종속 제거)
- 설정과 도메인 로직을 시각적으로 분리하고 싶을 때

**프로퍼티가 나은 경우**
- 팀이 이미 프로퍼티 방식에 익숙하고 모델이 단순한 경우
- 조건부 로직이 필요한 경우 (attribute는 상수 표현식만 가능)
- 기존 코드베이스 전체를 굳이 건드릴 이유가 없는 경우

중간에 섞어 두는 상태가 가장 피해야 할 결과입니다.

## 13. 모델 밖의 attribute들 (참고)

같은 흐름으로 다른 영역에도 attribute가 늘었습니다. 모델 문서 범위 밖이지만 위치만 정리해 둡니다.

| 네임스페이스 | 예시 |
|---|---|
| `Illuminate\Queue\Attributes` | `Tries`, `Timeout`, `Backoff`, `Queue`, `Connection`, `Delay`, `MaxExceptions`, `FailOnTimeout`, `UniqueFor`, `DebounceFor`, `WithoutRelations`, `DeleteWhenMissingModels` |
| `Illuminate\Console\Attributes` | `Signature`, `Description`, `Help`, `Hidden`, `Aliases`, `Usage` |
| `Illuminate\Routing\Attributes\Controllers` | `Middleware`, `WithoutMiddleware`, `Authorize` |
| `Illuminate\Foundation\Http\Attributes` | `RedirectTo`, `RedirectToRoute`, `ErrorBag`, `StopOnFirstFailure`, `FailOnUnknownFields` |
| `Illuminate\Http\Resources\Attributes` | `Collects`, `PreserveKeys` |
| `Illuminate\Container\Attributes` | `Config`, `DB`, `Cache`, `Log`, `Storage`, `Auth`, `CurrentUser`, `Context`, `Tag`, `Give`, `Bind`, `BindWhen`, `Singleton`, `Scoped`, `RouteParameter`, `RequestAttribute` |
| `Illuminate\Foundation\Testing\Attributes` | `Seed`, `Seeder`, `SetUp`, `TearDown`, `UnitTest` |
| `Illuminate\Database\Eloquent\Factories\Attributes` | `UseModel` (Factory 클래스에 부착) |

> 컨트롤러 attribute의 네임스페이스가 `Illuminate\Routing\Attributes`가 아니라 `Illuminate\Routing\Attributes\Controllers`라는 점은 임포트할 때 자주 틀리는 지점입니다.
