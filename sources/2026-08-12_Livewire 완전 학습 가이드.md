# 1부 — 기초

## 1. Livewire란 무엇인가

### 한 줄 요약

**"PHP 클래스의 프로퍼티를 바꾸면, 화면이 알아서 갱신된다."**

Vue나 React가 하는 일(상태 → 화면 자동 반영)을 **서버 사이드 PHP에서** 하는 프레임워크입니다.

### 기존 Laravel 방식과 뭐가 다른가

검색 기능이 있는 게시글 목록을 만든다고 해봅시다.

**기존 방식 (Controller + Blade + JS)**

```php
// 1. 컨트롤러
class PostController extends Controller
{
    public function index(Request $request)
    {
        $posts = Post::where('title', 'like', "%{$request->search}%")
            ->paginate(10);

        return view('posts.index', compact('posts'));
    }
}
```

```blade
{{-- 2. 뷰 --}}
<form action="/posts" method="GET">
    <input name="search" value="{{ request('search') }}">
    <button>검색</button>
</form>
@foreach ($posts as $post) ... @endforeach
```

실시간 검색을 원하면 여기에 **3. JS를 추가**해야 합니다. axios로 API를 부르고, JSON을 받고, DOM을 직접 갱신하거나 Vue 컴포넌트를 하나 더 만들고... 그러면 **API 라우트도 하나 더** 만들어야 하고, 검증 로직도 두 곳(웹/API)에 생깁니다.

**Livewire 방식**

```php
<?php
use Livewire\Component;
use App\Models\Post;

new class extends Component {
    public string $search = '';

    public function render()
    {
        return $this->view([
            'posts' => Post::where('title', 'like', "%{$this->search}%")->get(),
        ]);
    }
};
?>

<div>
    <input type="text" wire:model.live="search" placeholder="검색...">

    @foreach ($posts as $post)
        <article wire:key="{{ $post->id }}">{{ $post->title }}</article>
    @endforeach
</div>
```

파일 하나. JS 없음. API 라우트 없음. 타이핑할 때마다 목록이 실시간으로 바뀝니다.

### 그래서 어떤 장단점이 있나

| 항목 | 평가 |
|---|---|
| 개발 속도 | 화면 하나에 파일 하나. 컨트롤러/API/JS 왕복이 없어짐 |
| 학습 곡선 | Laravel/Blade를 알면 진입 장벽이 낮음 |
| 검증 로직 | Laravel의 `validate()`를 그대로 사용 |
| 인증/권한 | `Auth`, `Gate`, `Policy` 그대로 사용 |
| **네트워크 왕복** | **모든 상호작용이 HTTP 요청.** 지연이 있는 환경에서는 체감이 나쁨 |
| **상태 전송량** | public 프로퍼티가 매 요청마다 왕복. 큰 배열/컬렉션을 담으면 무거워짐 |
| 복잡한 UI | 드래그, 캔버스, 실시간 애니메이션 등은 Alpine.js/JS 병행 필요 |

**적합한 곳**: 관리자 페이지, CRUD, 대시보드, 폼 위주 화면, 사내 도구
**부적합한 곳**: 오프라인 우선 앱, 밀리초 단위 반응이 필요한 UI, 채팅/게임

> **NativePHP 맥락에서는 이 단점이 대부분 사라집니다.** 앱이 기기 안에서 돌기 때문에 "네트워크 왕복"이 실제로는 localhost 호출입니다. 지연이 사실상 0이라 Livewire의 최대 약점이 무력화됩니다. 이것이 NativePHP에서 Livewire를 권장하는 핵심 이유입니다.

## 2. 동작 원리 이해하기

이 절을 이해하면 나중에 겪는 대부분의 버그가 스스로 설명됩니다. **건너뛰지 마세요.**

### 최초 렌더링

1. 브라우저가 페이지를 요청
2. Laravel이 Livewire 컴포넌트를 실행 → HTML 생성
3. 이 HTML에 **`snapshot`** 이라는 JSON이 함께 붙어서 나감

`snapshot`은 컴포넌트의 현재 상태를 직렬화한 것입니다. 실제로 브라우저 개발자도구에서 보면 이렇게 생겼습니다.

```html
<div wire:id="abc123" wire:snapshot='{"data":{"search":"","count":0},"memo":{...},"checksum":"..."}'>
    <!-- 렌더링된 HTML -->
</div>
```

### 상호작용이 일어날 때

사용자가 버튼을 클릭하면:

```
[브라우저]                          [서버]
   |                                  |
   |-- POST /livewire-{hash}/update ->|
   |   { snapshot, calls: [           |
   |       {method: 'increment'} ] }  |
   |                                  | 1. snapshot으로 컴포넌트 재구성 (hydrate)
   |                                  | 2. increment() 실행
   |                                  | 3. render() 다시 호출 → 새 HTML
   |                                  | 4. 상태를 다시 직렬화 (dehydrate)
   |<-- { snapshot, html } -----------|
   |                                  |
   | 5. 기존 DOM과 새 HTML을 비교(morph)
   |    → 바뀐 부분만 갈아끼움
```

핵심 용어 3개:

- **Hydration (수화)**: JSON snapshot → PHP 객체 복원
- **Dehydration (탈수)**: PHP 객체 → JSON snapshot 직렬화
- **Morphing**: 기존 DOM과 새 HTML을 비교해 **바뀐 부분만** 교체. 전체를 갈아끼우지 않기 때문에 input 포커스나 스크롤 위치가 유지됨

### 여기서 나오는 중요한 결론들

**결론 1. 컴포넌트 인스턴스는 요청 사이에 살아있지 않다**

```php
new class extends Component {
    public $count = 0;
    private $cache = [];   // ❌ 다음 요청에서 사라짐

    public function mount()
    {
        $this->cache = expensiveThing();  // 소용없음
    }
};
```

`public` 프로퍼티만 snapshot에 담겨 왕복합니다. `private`/`protected`는 매 요청마다 초기값으로 리셋됩니다.

**결론 2. public 프로퍼티는 전부 클라이언트로 나간다**

```php
public $user;              // 브라우저가 다 볼 수 있음
public $isAdmin = false;   // ❌ 사용자가 조작 가능!
protected $apiKey;         // 안전 (하지만 요청 간 유지 안 됨)
```

브라우저 개발자도구에서 `$wire.isAdmin = true` 하면 그냥 바뀝니다. **권한 판단을 public 프로퍼티에 의존하면 안 됩니다.** 서버에서 매번 `Auth::user()->isAdmin()`으로 확인하거나 `#[Locked]`를 씁니다.

**결론 3. public 프로퍼티에 담을 수 있는 타입이 제한적이다**

JSON으로 직렬화 가능해야 합니다.

```php
// ✅ 가능
public string $name;
public int $count;
public bool $flag;
public array $items;
public ?Post $post;                  // Eloquent 모델 (ID만 저장 후 재조회)
public Collection $posts;            // Eloquent 컬렉션
public Carbon $date;                 // DateTime 계열
public Illuminate\Support\Collection $tags;

// ❌ 불가능
public Closure $callback;            // 클로저
public PDO $connection;              // 리소스
public SomeRandomClass $service;     // 일반 객체 (Wireable 구현 없이는)
```

**결론 4. `render()`는 매 요청마다 실행된다**

버튼 하나 눌러도 `render()`가 통째로 다시 돕니다. 여기에 무거운 쿼리를 넣으면 매 클릭마다 그 쿼리가 돕니다. → **Computed Properties**로 해결(9장).

## 3. 설치와 첫 컴포넌트

### 설치

```bash
# 새 프로젝트라면 스타터 킷에 이미 포함
laravel new my-app     # Livewire 스타터 킷 선택 시 v4 자동 설치

# 기존 프로젝트
composer require livewire/livewire
php artisan optimize:clear
```

레이아웃 파일에 스크립트/스타일이 필요합니다. Laravel 11+ 기본 레이아웃을 쓴다면 자동 주입되지만, 직접 만든 레이아웃이라면:

```blade
{{-- resources/views/layouts/app.blade.php --}}
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>{{ $title ?? 'My App' }}</title>
    @vite(['resources/css/app.css', 'resources/js/app.js'])
    @livewireStyles   {{-- v3에서 필수. v4는 자동 주입되지만 명시해도 무방 --}}
</head>
<body>
    {{ $slot }}

    @livewireScripts
</body>
</html>
```

### 첫 컴포넌트: 카운터

```bash
php artisan make:livewire counter
```

생성 위치: `resources/views/components/⚡counter.blade.php`

> **⚡ 이모지가 붙는 이유**: v4부터 파일명에 ⚡를 붙여 일반 Blade 파일과 구분합니다. 에디터 파일 트리와 검색에서 바로 눈에 띕니다. 거슬리면 `config/livewire.php`에서 `'make_command' => ['emoji' => false]`로 끕니다.

```php
<?php

use Livewire\Component;

new class extends Component {
    public int $count = 0;

    public function increment()
    {
        $this->count++;
    }

    public function decrement()
    {
        $this->count--;
    }

    public function reset_()
    {
        $this->count = 0;
    }
};

?>

<div class="p-6 text-center">
    <h1 class="text-6xl font-bold">{{ $count }}</h1>

    <div class="mt-4 flex gap-2 justify-center">
        <button wire:click="decrement" class="px-4 py-2 bg-gray-200 rounded">−</button>
        <button wire:click="increment" class="px-4 py-2 bg-gray-200 rounded">+</button>
        <button wire:click="reset_"    class="px-4 py-2 bg-red-100 rounded">리셋</button>
    </div>
</div>
```

> ⚠️ `reset`은 Livewire의 내장 메서드 이름이라 오버라이드하면 문제가 생깁니다. `reset_`이나 `resetCount` 같은 다른 이름을 쓰세요. 예약된 이름: `reset`, `mount`, `render`, `dispatch`, `validate`, `fill`, `all` 등.

### 화면에 띄우기

**방법 A. 기존 Blade 안에 삽입**

```blade
<div>
    <h1>대시보드</h1>
    <livewire:counter />
</div>
```

> ⚠️ **v4부터 태그를 반드시 닫아야 합니다.** `<livewire:counter>`처럼 열어두면 뒤 내용을 slot으로 해석해서 렌더링이 깨집니다.

**방법 B. 페이지 전체로 라우팅**

```php
// routes/web.php
use Illuminate\Support\Facades\Route;

Route::livewire('/counter', 'counter');
```

> **v3 대비**
> ```php
> // v3
> Route::get('/counter', \App\Livewire\Counter::class);
>
> // v4 (권장. SFC/MFC는 이 방식이 필수)
> Route::livewire('/counter', 'counter');
> ```

### 페이지 컴포넌트 만들기

페이지 전용 컴포넌트는 `pages::` 네임스페이스로 분리하면 정리가 됩니다.

```bash
php artisan make:livewire pages::post.index
# → resources/views/pages/post/⚡index.blade.php
```

```php
Route::livewire('/posts', 'pages::post.index');
```

레이아웃과 타이틀 지정:

```php
<?php

use Livewire\Component;
use Livewire\Attributes\{Layout, Title};

#[Layout('layouts::app')]
#[Title('게시글 목록')]
new class extends Component {
    // ...
};
```

## 4. 컴포넌트 3가지 형식

v4에서는 세 가지 방식 중 고를 수 있습니다. **셋 다 컴포넌트 이름은 동일**하므로 나중에 자유롭게 전환할 수 있습니다.

### (1) Single-File Component — SFC (기본값)

```bash
php artisan make:livewire post.create
# → resources/views/components/post/⚡create.blade.php
```

```php
<?php

use Livewire\Component;

new class extends Component {
    public string $title = '';

    public function save()
    {
        // ...
    }
};

?>

<div>
    <input wire:model="title">
    <button wire:click="save">저장</button>
</div>
```

**언제 쓰나**: 대부분의 경우. 로직과 뷰가 같은 파일에 있어 파일 왕복이 없습니다.

### (2) Multi-File Component — MFC

```bash
php artisan make:livewire post.create --mfc --js --css --test
```

```
resources/views/components/post/⚡create/
├── create.php          # PHP 클래스
├── create.blade.php    # Blade 템플릿
├── create.js           # JavaScript (선택)
├── create.css          # 스코프 CSS (선택)
├── create.global.css   # 전역 CSS (선택)
└── create.test.php     # Pest 테스트 (선택)
```

**언제 쓰나**: 컴포넌트가 커졌을 때, JS가 상당히 들어갈 때, IDE 지원이 중요할 때.

### (3) Class-based (v3 방식)

```bash
php artisan make:livewire CreatePost --class
```

```php
// app/Livewire/CreatePost.php
<?php

namespace App\Livewire;

use Livewire\Component;

class CreatePost extends Component
{
    public string $title = '';

    public function save() { /* ... */ }

    public function render()
    {
        return view('livewire.create-post');
    }
}
```

```blade
{{-- resources/views/livewire/create-post.blade.php --}}
<div>
    <input wire:model="title">
</div>
```

**언제 쓰나**: v3에서 마이그레이션 중일 때, 팀 컨벤션이 이미 잡혀 있을 때, 상속/트레이트 구조가 복잡할 때.

기본값을 class로 바꾸려면:

```php
// config/livewire.php
'make_command' => [
    'type'  => 'class',   // 'sfc' | 'mfc' | 'class'
    'emoji' => false,
],
```

### 형식 간 변환

```bash
php artisan livewire:convert post.create        # 자동 감지 후 반대 형식으로
php artisan livewire:convert post.create --mfc  # 명시적으로 MFC로
php artisan livewire:convert post.create --sfc  # 명시적으로 SFC로
```

### 파일 경로 ↔ 컴포넌트 이름 매핑

| 형식 | 파일 경로 | 컴포넌트 이름 |
|---|---|---|
| SFC | `resources/views/components/post/⚡create.blade.php` | `post.create` |
| MFC | `resources/views/components/post/⚡create/create.php` | `post.create` |
| Class | `app/Livewire/Post/Create.php` | `post.create` |
| SFC (네임스페이스) | `resources/views/pages/post/⚡create.blade.php` | `pages::post.create` |

**중요한 규칙 하나**: 템플릿에는 **루트 엘리먼트가 정확히 하나** 있어야 합니다.

```blade
{{-- ✅ --}}
<div>
    <h1>제목</h1>
    <p>내용</p>
</div>

{{-- ❌ 루트가 둘 --}}
<h1>제목</h1>
<p>내용</p>
```

Livewire가 이 루트 엘리먼트에 `wire:id`를 붙여 컴포넌트를 추적하기 때문입니다.

## 5. Properties (상태)

### 기본

```php
new class extends Component {
    public string $name = '홍길동';
    public int $age = 30;
    public array $tags = ['php', 'laravel'];
};
```

```blade
<div>
    <p>{{ $name }} ({{ $age }}세)</p>
    {{-- public 프로퍼티는 $this 없이 바로 접근 가능 --}}

    <p>{{ $this->name }}</p>  {{-- 이렇게도 됨 --}}
</div>
```

`protected`/`private`는 `$this->`로만 접근합니다.

```php
public $title = '제목';         // {{ $title }}
protected $apiKey = 'secret';   // {{ $this->apiKey }} — 클라이언트로 나가지 않음
```

### wire:model — 양방향 바인딩

이게 Livewire의 심장입니다.

```blade
<input type="text" wire:model="name">
```

이렇게 하면 input과 `$name` 프로퍼티가 연결됩니다.

**기본 동작은 "지연"입니다.** 타이핑해도 서버에 요청이 가지 않고, 다음 액션(버튼 클릭 등)이 일어날 때 값이 함께 전송됩니다. 이건 의도된 설계입니다 — 글자마다 요청을 보내면 낭비니까요.

#### 수식어(modifier)

```blade
{{-- 타이핑할 때마다 즉시 서버 요청 --}}
<input wire:model.live="search">

{{-- 500ms 동안 입력이 멈추면 요청 (검색창에 필수) --}}
<input wire:model.live.debounce.500ms="search">

{{-- 250ms마다 최대 1회 요청 --}}
<input wire:model.live.throttle.250ms="search">

{{-- 포커스를 잃을 때 --}}
<input wire:model.blur="email">

{{-- change 이벤트 발생 시 (select에 적합) --}}
<select wire:model.change="category">

{{-- Enter 키 또는 blur 시 --}}
<input wire:model.blur.enter="search">

{{-- 숫자로 캐스팅 --}}
<input type="number" wire:model.number="quantity">

{{-- 앞뒤 공백 제거 --}}
<input wire:model.trim="username">

{{-- 빈 문자열을 null로 --}}
<input wire:model.fill="nickname">
```

> **v3 대비 — 중요한 변경**
> v3에서 `.blur`/`.change`는 **네트워크 요청 타이밍만** 제어했고, 클라이언트 상태(`$wire.property`)는 타이핑 즉시 갱신됐습니다.
> v4에서는 **클라이언트 상태 동기화 타이밍까지** 제어합니다.
> ```blade
> <!-- v3 -->
> <input wire:model.blur="title">
>
> <!-- v4에서 v3와 동일하게 만들려면 -->
> <input wire:model.live.blur="title">
> ```
> `.lazy`는 그대로 호환됩니다.

### Eloquent 모델 바인딩

```php
use App\Models\Post;

new class extends Component {
    public Post $post;      // 모델 자체를 프로퍼티로

    public function mount(Post $post)
    {
        $this->post = $post;
    }
};
```

Livewire는 모델을 통째로 직렬화하지 않고 **ID만 저장했다가 다음 요청에서 다시 조회**합니다. 그래서 이런 문제가 생깁니다.

```php
// ❌ 관계를 미리 로드해도 다음 요청에서 사라짐
public function mount(Post $post)
{
    $this->post = $post->load('comments');
}
```

해결책 — `#[Computed]`를 쓰거나, 필요한 값만 스칼라로 뽑아두거나, `render()`에서 매번 조회합니다.

```php
use Livewire\Attributes\Computed;

#[Computed]
public function comments()
{
    return $this->post->comments()->latest()->get();
}
```

```blade
@foreach ($this->comments as $comment) ... @endforeach
```

### 프로퍼티 관련 어트리뷰트

#### `#[Locked]` — 프론트엔드 조작 방지

```php
use Livewire\Attributes\Locked;

new class extends Component {
    #[Locked]
    public int $postId;      // 클라이언트가 값을 바꾸려 하면 예외 발생

    public string $comment = '';

    public function save()
    {
        // $this->postId를 신뢰하고 쓸 수 있음
        Comment::create([
            'post_id' => $this->postId,
            'body'    => $this->comment,
        ]);
    }
};
```

**ID류 프로퍼티에는 습관적으로 붙이세요.** 안 붙이면 사용자가 개발자도구로 `$wire.postId = 999` 해서 남의 글에 댓글을 달 수 있습니다.

#### `#[Session]` — 세션에 자동 저장

```php
use Livewire\Attributes\Session;

#[Session]
public string $sortBy = 'created_at';   // 페이지를 떠났다 돌아와도 유지

#[Session(key: 'user-filter')]

```

#### `#[Url]` — URL 쿼리스트링과 동기화

16장에서 자세히 다룹니다.

```php

#[Url]

```

### `$this->reset()` / `$this->fill()` / `$this->pull()`

```php
public function clearForm()
{
    $this->reset();                       // 모든 프로퍼티를 초기값으로
    $this->reset('title', 'body');        // 특정 프로퍼티만
    $this->resetExcept('search');         // 특정 것 제외하고 전부

    $this->fill([                         // 여러 값 한 번에 세팅
        'title' => '기본 제목',
        'body'  => '',
    ]);

    $value = $this->pull('title');        // 값을 꺼내고 리셋
}
```

> ```php
> // ❌ 위험
> public function delete(int $id)
> {
>     Post::find($id)->delete();   // 남의 글도 지워짐
> }
>
> // ✅ 권한 확인
> public function delete(int $id)
> {
>     $post = Post::findOrFail($id);
>     $this->authorize('delete', $post);
>     $post->delete();
> }
> ```

### Form 객체 — 재사용 가능한 폼

폼 로직이 커지면 별도 클래스로 분리합니다.

```bash
php artisan livewire:form PostForm
# → app/Livewire/Forms/PostForm.php
```

```php
<?php

namespace App\Livewire\Forms;

use App\Models\Post;
use Livewire\Attributes\Validate;
use Livewire\Form;

class PostForm extends Form
{
    public ?Post $post = null;

    #[Validate('required|min:3|max:255')]
    public string $title = '';

    #[Validate('required|min:10')]
    public string $content = '';

    #[Validate('nullable|array')]
    public array $tags = [];

    /** 수정 모드로 채우기 */
    public function setPost(Post $post): void
    {
        $this->post    = $post;
        $this->title   = $post->title;
        $this->content = $post->content;
        $this->tags    = $post->tags->pluck('name')->toArray();
    }

    public function store(): Post
    {
        $this->validate();

        $post = Post::create($this->only('title', 'content'));
        $post->syncTags($this->tags);

        $this->reset();

        return $post;
    }

    public function update(): Post
    {
        $this->validate();

        $this->post->update($this->only('title', 'content'));
        $this->post->syncTags($this->tags);

        return $this->post;
    }
}
```

사용:

```php
<?php

use Livewire\Component;
use App\Livewire\Forms\PostForm;
use App\Models\Post;

new class extends Component {
    public PostForm $form;

    public function mount(?Post $post = null)
    {
        if ($post?->exists) {
            $this->form->setPost($post);
        }
    }

    public function save()
    {
        $this->form->post
            ? $this->form->update()
            : $this->form->store();

        session()->flash('message', '저장되었습니다.');

        return $this->redirect('/posts', navigate: true);
    }
};

?>

<form wire:submit="save">
    <input wire:model="form.title">
    @error('form.title') <span class="text-red-600">{{ $message }}</span> @enderror

    <textarea wire:model="form.content"></textarea>
    @error('form.content') <span class="text-red-600">{{ $message }}</span> @enderror

    <button type="submit">저장</button>
</form>
```

> **Form 객체를 쓰면 좋은 이유**
> - 생성 폼과 수정 폼이 같은 Form 클래스를 공유
> - 컴포넌트가 얇아짐 (FormRequest와 비슷한 역할 + 상태까지 담당)
> - `$this->form->only()`, `$this->form->all()`, `$this->form->reset()`, `$this->form->pull()` 사용 가능


# 2부 — 실무 필수

## 8. Lifecycle Hooks

컴포넌트의 생애 주기 곳곳에 끼어들 수 있습니다.

### 전체 흐름

```
[최초 요청]
  boot()          → 매 요청 시작 시 (최초 포함)
  mount()         → 최초 1회만. 생성자 역할
  booted()        → boot + mount 이후
  rendering()     → render() 직전
  render()
  rendered()      → render() 이후
  dehydrate()     → 상태 직렬화 직전

[후속 요청]
  hydrate()       → 상태 복원 직후
  boot()
  booted()
  updating($name, $value)   → 프로퍼티 변경 직전
  updated($name, $value)    → 프로퍼티 변경 직후
  [액션 실행]
  rendering()
  render()
  rendered()
  dehydrate()
```

### `mount()` — 초기화

```php
use App\Models\Post;

new class extends Component {
    public Post $post;
    public string $title = '';
    public array $availableTags = [];

    public function mount(Post $post)
    {
        $this->post  = $post;
        $this->title = $post->title;
        $this->availableTags = Tag::pluck('name')->toArray();
    }
};
```

> `mount()`는 **최초 1회만** 실행됩니다. 버튼을 눌러도 다시 실행되지 않습니다. 컨트롤러의 생성자 + `index()` 초반 세팅을 합친 역할입니다.

파라미터가 프로퍼티명과 같으면 `mount()`를 생략할 수 있습니다.

```php
new class extends Component {
    public string $title;   // <livewire:post.edit title="..." /> 에서 자동 주입
};
```

### `boot()` / `booted()` — 매 요청마다

`private`/`protected` 프로퍼티를 매 요청마다 다시 세팅할 때 씁니다.

```php
new class extends Component {
    public int $postId;
    protected Post $post;      // 직렬화 불가 → 매번 다시 세팅

    public function boot()
    {
        $this->post = Post::findOrFail($this->postId);
    }

    public function publish()
    {
        $this->post->update(['published_at' => now()]);
    }
};
```

의존성 주입도 됩니다.

```php
use App\Services\PostService;

protected PostService $service;

public function boot(PostService $service)
{
    $this->service = $service;
}
```

### `updating()` / `updated()` — 프로퍼티 변경 감지

```php
new class extends Component {
    public string $search = '';
    public string $category = '';

    // 모든 프로퍼티 대상
    public function updating(string $name, mixed $value)
    {
        logger("변경 예정: {$name} = {$value}");
    }

    public function updated(string $name, mixed $value)
    {
        // 검색어나 카테고리가 바뀌면 페이지 1로
        if (in_array($name, ['search', 'category'])) {
            $this->resetPage();
        }
    }

    // 특정 프로퍼티만 — updated + 프로퍼티명(PascalCase)
    public function updatedSearch(string $value)
    {
        $this->resetPage();
    }

    public function updatingCategory(string $value)
    {
        // 변경 전 값 검사
    }
};
```

배열/중첩 프로퍼티의 경우:

```php
public array $form = ['title' => '', 'body' => ''];

// form 전체
public function updatedForm($value, $key)
{
    // $key = 'title'
}

// form.title 만
public function updatedFormTitle($value)
{
    // ...
}
```

### `hydrate()` / `dehydrate()`

```php
public function hydrate()
{
    // snapshot에서 복원된 직후
}

public function dehydrate()
{
    // 직렬화 직전. 마지막 정리 작업
}
```

### `rendering()` / `rendered()`

```php
public function rendering($view, $data)
{
    // render() 직전. 뷰 데이터 조작 가능
}

public function rendered($view, $html)
{
    // 최종 HTML을 볼 수 있음. 디버깅에 유용
}
```

### `exception()` — 예외 가로채기

```php
public function exception($e, $stopPropagation)
{
    if ($e instanceof ModelNotFoundException) {
        $this->addError('search', '해당 항목을 찾을 수 없습니다.');
        $stopPropagation();   // 에러 페이지로 안 넘어감
    }
}
```

## 9. Computed Properties

### 문제 상황

```php
new class extends Component {
    public string $search = '';

    public function render()
    {
        return $this->view([
            // ❌ 버튼을 하나 눌러도 이 쿼리가 매번 실행됨
            'posts' => Post::with('author')->where(...)->get(),
        ]);
    }
};
```

### 해결

```php
use Livewire\Attributes\Computed;

new class extends Component {
    public string $search = '';

    #[Computed]
    public function posts()
    {
        return Post::with('author')
            ->where('title', 'like', "%{$this->search}%")
            ->latest()
            ->get();
    }
};
```

```blade
<div>
    {{-- $this-> 를 반드시 붙여야 함 --}}
    @foreach ($this->posts as $post)
        <article wire:key="{{ $post->id }}">{{ $post->title }}</article>
    @endforeach

    <p>총 {{ $this->posts->count() }}건</p>
    {{-- 여러 번 써도 쿼리는 1회만 실행 (요청 내 메모이제이션) --}}
</div>
```

**핵심**: 한 요청 안에서 여러 번 접근해도 **첫 호출 결과를 재사용**합니다.

### 캐시 옵션

```php
// 요청 간에도 유지 (컴포넌트가 살아있는 동안)
#[Computed(persist: true)]
public function user()
{
    return User::find($this->userId);
}

// 캐시 지속 시간 지정 (초)
#[Computed(persist: true, seconds: 3600)]
public function stats() { /* ... */ }

// Laravel 캐시 드라이버 사용 (모든 사용자 공유)
#[Computed(cache: true)]
public function popularTags()
{
    return Tag::withCount('posts')->orderByDesc('posts_count')->take(10)->get();
}

// 캐시 키 지정
#[Computed(cache: true, key: 'popular-tags')]
public function popularTags() { /* ... */ }
```

### 캐시 무효화

```php
public function addPost()
{
    Post::create([...]);

    unset($this->posts);          // 캐시 삭제 → 다음 접근 시 재계산
}
```

### PHP 쪽에서 사용

```php
public function publishAll()
{
    // 메서드 호출이 아니라 프로퍼티 접근처럼
    foreach ($this->posts as $post) {
        $post->publish();
    }
}
```

### 언제 쓰나 — 판단 기준

| 상황 | 방법 |
|---|---|
| DB 조회 결과 | `#[Computed]` |
| 단순 계산 (합계 등) | `#[Computed]` 또는 Blade 안에서 직접 |
| 사용자 입력값 | public 프로퍼티 |
| 요청 사이에 유지되어야 하는 상태 | public 프로퍼티 |
| 매번 최신값이어야 하는 것 | `render()` 안에서 조회 |

> **왜 컬렉션을 public 프로퍼티에 담으면 안 되나**
> ```php
> public Collection $posts;   // ❌ 매 요청마다 전체가 JSON으로 왕복
> ```
> 게시글 100건이면 100건의 데이터가 매 클릭마다 브라우저 ↔ 서버를 왕복합니다. `#[Computed]`는 서버에서만 계산되고 HTML만 나갑니다.

## 10. 렌더링 규칙과 wire:key

### `render()` 메서드

**SFC**에서는 `render()`가 없어도 됩니다. 파일 아래쪽 HTML이 자동으로 뷰가 됩니다. 뷰에 데이터를 넘기고 싶을 때만 정의합니다.

```php
public function render()
{
    return $this->view([
        'author'      => Auth::user(),
        'currentTime' => now(),
    ]);
}
```

**Class-based**에서는 필수입니다.

```php
public function render()
{
    return view('livewire.post-list', [
        'posts' => Post::latest()->get(),
    ]);
}
```

### 뷰에 데이터를 주는 3가지 방법 비교

```php
new class extends Component {
    // 1. public 프로퍼티 — 상태. 매 요청 왕복.
    public string $search = '';

    // 2. computed — 서버 계산. 왕복 없음. $this-> 로 접근.
    #[Computed]
    public function posts() { return Post::all(); }

    // 3. render() 전달 — 매 요청 재계산. 왕복 없음. 바로 접근.
    public function render()
    {
        return $this->view(['now' => now()]);
    }
};
```

```blade
{{ $search }}         {{-- 1 --}}
{{ $this->posts }}    {{-- 2 --}}
{{ $now }}            {{-- 3 --}}
```

### Morphing과 `wire:key` — 반드시 이해할 것

Livewire는 새 HTML과 기존 DOM을 **위에서부터 순서대로 비교**합니다. 리스트에서 항목이 추가/삭제/정렬되면 이 비교가 어긋나 엉뚱한 결과가 나옵니다.

```blade
{{-- ❌ 삭제하면 엉뚱한 항목이 사라진 것처럼 보임 --}}
@foreach ($posts as $post)
    <div>
        <input wire:model="titles.{{ $post->id }}">
        <button wire:click="delete({{ $post->id }})">삭제</button>
    </div>
@endforeach

{{-- ✅ --}}
@foreach ($posts as $post)
    <div wire:key="post-{{ $post->id }}">
        <input wire:model="titles.{{ $post->id }}">
        <button wire:click="delete({{ $post->id }})">삭제</button>
    </div>
@endforeach
```

**규칙**: 반복문 안의 최상위 엘리먼트에는 **항상** `wire:key`를 붙입니다. 값은 그 항목의 고유 ID여야 합니다 (`$loop->index`는 순서가 바뀌면 무의미하므로 부적합).

중첩 컴포넌트도 마찬가지입니다.

```blade
@foreach ($posts as $post)
    <livewire:post-card :post="$post" wire:key="card-{{ $post->id }}" />
@endforeach
```

> v4에서 `smart_wire_keys`가 기본 `true`가 되어 깊게 중첩된 컴포넌트의 키 문제는 줄었지만, **반복문에서는 여전히 직접 붙여야 합니다.**

### `wire:ignore` — DOM을 건드리지 않게

Select2, Flatpickr, TinyMCE 같은 JS 라이브러리가 조작한 DOM은 Livewire가 갈아엎으면 깨집니다.

```blade
{{-- 이 안쪽은 morphing에서 제외 --}}
<div wire:ignore>
    <select id="my-select2">...</select>
</div>

{{-- 자기 자신만 제외, 자식은 갱신 허용 --}}
<div wire:ignore.self>
    <span>{{ $count }}</span>
</div>
```

### `wire:replace` (v4)

morphing 대신 **통째로 교체**하게 합니다. 애니메이션 재시작 등에 유용합니다.

```blade
<div wire:replace>
    <div class="animate-fade-in">{{ $message }}</div>
</div>
```

### `wire:poll` — 주기적 갱신

```blade
{{-- 2.5초마다 자동 재렌더링 (기본값) --}}
<div wire:poll>...</div>

{{-- 5초마다 --}}
<div wire:poll.5s>...</div>

{{-- 특정 메서드 호출 --}}
<div wire:poll.10s="refreshStats">...</div>

{{-- 탭이 보일 때만 (백그라운드 탭에서는 중지) --}}
<div wire:poll.visible>...</div>

{{-- 백그라운드에서도 계속 --}}
<div wire:poll.keep-alive>...</div>
```

> v4에서 폴링은 **논블로킹**입니다. 다른 요청을 막지 않고, 막히지도 않습니다.

## 11. Loading States

사용자에게 "지금 처리 중"임을 보여주는 것은 Livewire에서 특히 중요합니다. 모든 조작이 네트워크를 타기 때문입니다.

### 기본

```blade
{{-- 요청 중일 때만 표시 --}}
<div wire:loading>불러오는 중...</div>

{{-- 요청 중일 때 숨김 --}}
<div wire:loading.remove>내용</div>
```

### 특정 액션만 대상으로

```blade
<button wire:click="save">저장</button>
<button wire:click="delete">삭제</button>

{{-- save 중일 때만 --}}
<span wire:loading wire:target="save">저장 중...</span>

{{-- delete 중일 때만 --}}
<span wire:loading wire:target="delete">삭제 중...</span>

{{-- 여러 개 --}}
<span wire:loading wire:target="save, delete">처리 중...</span>

{{-- 파라미터까지 지정 --}}
<span wire:loading wire:target="delete(3)">3번 삭제 중...</span>

{{-- 특정 프로퍼티 갱신 중 --}}
<span wire:loading wire:target="search">검색 중...</span>

{{-- 특정 대상 제외 --}}
<span wire:loading wire:target.except="poll">처리 중...</span>
```

### 속성/클래스 조작

```blade
{{-- 로딩 중 disabled --}}
<button wire:click="save" wire:loading.attr="disabled">저장</button>

{{-- 로딩 중 클래스 추가 --}}
<button wire:click="save" wire:loading.class="opacity-50 cursor-wait">저장</button>

{{-- 로딩 중 클래스 제거 --}}
<button wire:click="save" wire:loading.class.remove="bg-blue-600">저장</button>
```

### `data-loading` 속성 (v4)

v4부터 요청을 유발하는 모든 엘리먼트에 자동으로 `data-loading` 속성이 붙습니다. Tailwind와 조합하면 매우 간결해집니다.

```blade
<button wire:click="save"
        class="bg-blue-600 text-white px-4 py-2 rounded
               data-loading:opacity-50 data-loading:pointer-events-none">
    저장
</button>
```

### 지연 표시 (깜빡임 방지)

빠른 요청에서 로딩 인디케이터가 번쩍이는 걸 막습니다.

```blade
<div wire:loading.delay>로딩...</div>          {{-- 200ms 후 --}}
<div wire:loading.delay.shortest>...</div>     {{-- 50ms --}}
<div wire:loading.delay.shorter>...</div>      {{-- 100ms --}}
<div wire:loading.delay.short>...</div>        {{-- 150ms --}}
<div wire:loading.delay.long>...</div>         {{-- 300ms --}}
<div wire:loading.delay.longer>...</div>       {{-- 500ms --}}
<div wire:loading.delay.longest>...</div>      {{-- 1000ms --}}
```

### 실전 예시 — 스켈레톤 + 버튼

```blade
<div>
    <form wire:submit="search" class="flex gap-2">
        <input type="text" wire:model="query" class="border rounded p-2 flex-1">
        <button type="submit"
                wire:loading.attr="disabled"
                wire:target="search"
                class="bg-blue-600 text-white px-4 py-2 rounded disabled:opacity-50">
            <span wire:loading.remove wire:target="search">검색</span>
            <span wire:loading wire:target="search" class="flex items-center gap-2">
                <svg class="animate-spin h-4 w-4" viewBox="0 0 24 24">
                    <circle class="opacity-25" cx="12" cy="12" r="10"
                            stroke="currentColor" stroke-width="4" fill="none"/>
                    <path class="opacity-75" fill="currentColor"
                          d="M4 12a8 8 0 018-8V0C5.4 0 0 5.4 0 12h4z"/>
                </svg>
                검색 중
            </span>
        </button>
    </form>

    {{-- 스켈레톤 --}}
    <div wire:loading.delay wire:target="search" class="mt-4 space-y-2">
        @for ($i = 0; $i < 3; $i++)
            <div class="h-16 bg-gray-200 rounded animate-pulse"></div>
        @endfor
    </div>

    {{-- 결과 --}}
    <div wire:loading.remove wire:target="search" class="mt-4">
        @foreach ($this->results as $result)
            <div wire:key="{{ $result->id }}">{{ $result->title }}</div>
        @endforeach
    </div>
</div>
```

### 기타 상태 디렉티브

```blade
{{-- 오프라인일 때 --}}
<div wire:offline class="bg-red-100 p-2">인터넷 연결이 끊겼습니다</div>
```

## 12. Events (컴포넌트 간 통신)

컴포넌트들은 서로를 직접 참조할 수 없습니다. 대신 **이벤트**로 통신합니다.

### 발행

```php
// 기본
$this->dispatch('post-created');

// 데이터와 함께 (이름 있는 인자만 가능)
$this->dispatch('post-created', postId: $post->id, title: $post->title);

// 특정 컴포넌트에게만
$this->dispatch('refresh')->to('post-list');
$this->dispatch('refresh')->to(PostList::class);

// 자기 자신에게만
$this->dispatch('refresh')->self();
```

Blade에서 직접:

```blade
<button wire:click="$dispatch('open-modal', { name: 'confirm-delete' })">삭제</button>
```

### 수신

```php
use Livewire\Attributes\On;

new class extends Component {
    #[On('post-created')]
    public function refreshList($postId, $title)
    {
        // 파라미터명이 dispatch의 인자명과 일치해야 함
        $this->reset('search');
    }

    // 동적 이벤트명
```

## 13. 컴포넌트 중첩과 Props

### 자식 컴포넌트 넣기

```blade
<livewire:post-card :post="$post" wire:key="{{ $post->id }}" />

{{-- 정적 값 --}}
<livewire:user-badge name="홍길동" :admin="true" />

{{-- 여러 값 한 번에 --}}
<livewire:post-card :$post :$showActions />
```

받는 쪽:

```php
new class extends Component {
    public Post $post;
    public bool $showActions = false;

    // mount() 생략 가능 — 이름이 일치하면 자동 주입
};
```

### props는 기본적으로 반응형이 아니다

**흔히 헷갈리는 부분입니다.**

```blade
<livewire:child :count="$parentCount" />
```

부모의 `$parentCount`가 바뀌어도 자식의 `$count`는 **자동으로 바뀌지 않습니다.** 최초 마운트 시점의 값만 전달됩니다.

React/Vue의 props와 다른 지점입니다. Livewire의 자식 컴포넌트는 자기만의 독립된 생명주기와 snapshot을 가지기 때문입니다.

### `#[Reactive]` — 반응형 props (v3+)

```php
use Livewire\Attributes\Reactive;

new class extends Component {
    #[Reactive]
    public int $count;    // 부모가 바뀌면 자식도 갱신됨
};
```

> ⚠️ 반응형 props는 부모가 재렌더링될 때마다 자식도 재렌더링됩니다. 남용하면 성능이 떨어집니다.

### `#[Modelable]` — 자식과 양방향 바인딩

커스텀 input 컴포넌트를 만들 때 씁니다.

```php
{{-- resources/views/components/⚡text-input.blade.php --}}
<?php

use Livewire\Component;
use Livewire\Attributes\Modelable;

new class extends Component {
    #[Modelable]
    public string $value = '';

    public string $label = '';
};

?>

<div>
    <label class="block text-sm">{{ $label }}</label>
    <input type="text" wire:model.live="value" class="border rounded p-2 w-full">
</div>
```

부모에서:

```blade
<livewire:text-input wire:model="title" label="제목" />
{{-- 자식의 $value가 부모의 $title과 연결됨 --}}
```

### `$parent` — 부모 메서드 호출

```blade
<button wire:click="$parent.removeItem({{ $item->id }})">삭제</button>
```

```php

{
    $this->dispatch('item-removed')->to('parent-component');
}
```

### Slots (v4 신기능)

v4부터 Livewire 컴포넌트도 slot을 지원합니다.

```blade
{{-- 사용하는 쪽 --}}

    <p>내용이 여기 들어갑니다.</p>

```



### 중첩 구조 설계 가이드

| 상황 | 권장 |
|---|---|
| 단순 반복 렌더링 (표시만) | Blade 컴포넌트 (`<x-post-card />`) |
| 각 항목이 자체 상태를 가짐 (인라인 편집 등) | Livewire 컴포넌트 |
| 항목이 100개 이상 | Blade 컴포넌트 — Livewire 컴포넌트 100개는 무겁습니다 |
| 무거운 위젯 일부만 갱신 | **Islands** (20장) |

> **성능 주의**: Livewire 컴포넌트 하나하나가 자체 snapshot을 가집니다. 리스트의 각 행을 Livewire 컴포넌트로 만들면 페이지 하나에 snapshot이 수십 개 생깁니다. 웬만하면 Blade 컴포넌트를 쓰고, 정말 독립적 상태가 필요할 때만 Livewire로 만드세요.

## 14. Pagination

```php
<?php

use Livewire\Component;
use Livewire\WithPagination;
use Livewire\Attributes\Url;
use App\Models\Post;

new class extends Component {
    use WithPagination;

    #[Url]
    public string $search = '';

    #[Url]
    public string $sortBy = 'created_at';

    public string $sortDirection = 'desc';

    public function updatedSearch()
    {
        $this->resetPage();     // 검색어가 바뀌면 1페이지로
    }

    public function sort(string $column)
    {
        if ($this->sortBy === $column) {
            $this->sortDirection = $this->sortDirection === 'asc' ? 'desc' : 'asc';
        } else {
            $this->sortBy = $column;
            $this->sortDirection = 'asc';
        }

        $this->resetPage();
    }

    public function render()
    {
        return $this->view([
            'posts' => Post::query()
                ->when($this->search, fn ($q) =>
                    $q->where('title', 'like', "%{$this->search}%"))
                ->orderBy($this->sortBy, $this->sortDirection)
                ->paginate(15),
        ]);
    }
};

?>

<div>
    <input type="text" wire:model.live.debounce.300ms="search"
           placeholder="검색..." class="border rounded p-2 w-full mb-4">

    <table class="w-full">
        <thead>
            <tr>
                <th wire:click="sort('title')" class="cursor-pointer text-left p-2">
                    제목
                    @if ($sortBy === 'title')
                        {{ $sortDirection === 'asc' ? '▲' : '▼' }}
                    @endif
                </th>
                <th wire:click="sort('created_at')" class="cursor-pointer text-left p-2">
                    작성일
                </th>
            </tr>
        </thead>
        <tbody>
            @forelse ($posts as $post)
                <tr wire:key="post-{{ $post->id }}" class="border-t">
                    <td class="p-2">{{ $post->title }}</td>
                    <td class="p-2">{{ $post->created_at->format('Y-m-d') }}</td>
                </tr>
            @empty
                <tr><td colspan="2" class="p-8 text-center text-gray-500">결과가 없습니다.</td></tr>
            @endforelse
        </tbody>
    </table>

    <div class="mt-4">
        {{ $posts->links() }}
    </div>
</div>
```

## 15. File Uploads

```php
<?php

use Livewire\Component;
use Livewire\WithFileUploads;
use Livewire\Attributes\Validate;

new class extends Component {
    use WithFileUploads;

    #[Validate('image|max:2048')]   // 2MB
    public $photo;

    #[Validate(['photos.*' => 'image|max:2048'])]
    public array $photos = [];

    public function save()
    {
        $this->validate();

        // storage/app/public/photos 에 저장
        $path = $this->photo->store('photos', 'public');

        // 원본 파일명 유지
        $path = $this->photo->storeAs(
            'photos',
            $this->photo->getClientOriginalName(),
            'public'
        );

        Photo::create(['path' => $path]);

        $this->reset('photo');
    }

    public function removePhoto(int $index)
    {
        unset($this->photos[$index]);
        $this->photos = array_values($this->photos);
    }
};

?>

         x-on:livewire-upload-finish="progress = 0"
         x-show="progress > 0">
        <div class="h-2 bg-gray-200 rounded">
            <div class="h-2 bg-blue-600 rounded" :style="`width: ${progress}%`"></div>
        </div>
    </div>

        <img src="{{ $photo->temporaryUrl() }}" class="w-32 h-32 object-cover mt-2">
```

## 17. wire:navigate — SPA처럼 만들기

일반 링크에 `wire:navigate`를 붙이면 페이지 전체를 새로 불러오지 않고 SPA처럼 전환됩니다. JS/CSS를 다시 파싱하지 않으므로 체감 속도가 크게 개선됩니다.

```blade
<a href="/posts" wire:navigate>게시글</a>

{{-- 마우스를 올렸을 때 미리 로드 --}}
<a href="/posts" wire:navigate.hover>게시글</a>

{{-- 히스토리 대체 (뒤로가기 시 건너뜀) --}}
<a href="/login" wire:navigate.replace>로그인</a>
```

PHP에서:

```php
return $this->redirect('/posts', navigate: true);
return $this->redirectRoute('posts.show', ['post' => $post], navigate: true);
```

### 현재 페이지 표시

```blade
<a href="/posts" wire:navigate wire:current="text-blue-600 font-bold">게시글</a>

{{-- 정확히 일치할 때만 --}}
<a href="/" wire:navigate wire:current.exact="font-bold">홈</a>

{{-- 하위 경로 포함 --}}
<a href="/admin" wire:navigate wire:current.strict="font-bold">관리자</a>
```

### 상태 유지 (`@persist`)

페이지가 바뀌어도 특정 엘리먼트를 유지합니다. 오디오 플레이어, 사이드바 스크롤 등에 씁니다.

```blade
@persist('player')
    <audio src="{{ $currentSong }}" controls></audio>
@endpersist

@persist('sidebar')
    <div class="overflow-y-scroll h-screen" wire:navigate:scroll>
        <!-- 사이드바 메뉴 -->
    </div>
@endpersist
```

> **v3 대비**: v3에서는 `wire:scroll`이었지만 v4에서는 `wire:navigate:scroll`로 바뀌었습니다.

### 네비게이션 이벤트

```blade
<script>
    document.addEventListener('livewire:navigate', (e) => {
        console.log('이동 시작', e.detail.url);
    });

    document.addEventListener('livewire:navigated', () => {
        // 서드파티 스크립트 재초기화 등
    });
</script>
```

> ⚠️ `wire:navigate`를 쓰면 페이지가 실제로 새로고침되지 않으므로, `DOMContentLoaded`에 걸어둔 스크립트가 다시 실행되지 않습니다. `livewire:navigated` 이벤트를 대신 쓰세요.

## 18. Alpine.js 연동

Livewire에는 Alpine.js가 기본 포함되어 있습니다. **서버 왕복이 필요 없는 UI 상호작용은 Alpine으로 처리**하는 것이 원칙입니다.

### 기본 조합

```blade
<div x-data="{ open: false }">
    <button @click="open = !open">토글</button>

    <div x-show="open" x-transition>
        여기는 서버 요청 없이 즉시 열고 닫힘
    </div>
</div>
```

### `$wire` — Alpine에서 Livewire 접근

```blade
<div x-data>
    {{-- 프로퍼티 읽기 --}}
    <span x-text="$wire.count"></span>

    {{-- 프로퍼티 쓰기 --}}
    <button @click="$wire.count++">증가</button>
    <button @click="$wire.search = ''">초기화</button>

    {{-- 메서드 호출 --}}
    <button @click="$wire.save()">저장</button>

    {{-- 결과 받기 (Promise) --}}
    <button @click="
        let result = await $wire.calculate(5);
        alert(result);
    ">계산</button>

    {{-- 재렌더링 없이 프로퍼티만 설정 --}}
    <button @click="$wire.$set('filter', 'active', false)">필터</button>

    {{-- 이벤트 발행 --}}
    <button @click="$wire.$dispatch('refresh')">새로고침</button>

    {{-- 강제 재렌더링 --}}
    <button @click="$wire.$refresh()">갱신</button>
</div>
```

### `$wire.$entangle` — 양방향 연결

Livewire 프로퍼티와 Alpine 상태를 묶습니다.

```php
new class extends Component {
    public bool $showModal = false;
};
```

```blade
<div x-data="{ open: $wire.$entangle('showModal') }">
    <button @click="open = true">열기</button>

    <div x-show="open" @click.away="open = false">
        모달 내용
```

| 데이터 저장/삭제 | Livewire |
| 권한 확인이 필요한 동작 | Livewire (서버) |

## 19. 컴포넌트 안의 JavaScript

### v4 — `<script>` 태그 직접 사용

view 기반 컴포넌트(SFC/MFC)에서는 `@script` 래퍼 없이 `<script>`를 쓸 수 있습니다. 이 스크립트는 별도 캐시 파일로 제공되고 `$wire`가 자동 바인딩됩니다.

```php
<?php
use Livewire\Component;

new class extends Component {
    public int $count = 0;
    public function increment() { $this->count++; }
};
?>

<div>
    <span>{{ $count }}</span>
    <button wire:click="increment">+</button>
    <button wire:click="$js.showAlert">알림</button>
</div>

<script>
    // this === $wire
    this.$js.showAlert = () => {
        alert(`현재 값: ${this.count}`);
    }

    // 컴포넌트 초기화 시 실행
    console.log('컴포넌트 로드됨');
</script>
```

> **v3 대비**
> ```blade
> {{-- v3 --}}
> @script
> <script>
>     $js('showAlert', () => { ... })
> </script>
> @endscript
>
> {{-- v4 --}}
> <script>
>     this.$js.showAlert = () => { ... }
> </script>
> ```

### `wire:ref` — 엘리먼트 참조 (v4)

```blade
<div wire:ref="modal" class="hidden">
    모달 내용
</div>

<button wire:click="$js.scrollToModal">모달로 이동</button>

<script>
    this.$js.scrollToModal = () => {
        this.$refs.modal.scrollIntoView({ behavior: 'smooth' });
    }
</script>
```

### `@assets` — 외부 라이브러리 1회 로드

```blade
@assets
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
@endassets

<div wire:ignore>
    <canvas id="chart"></canvas>
</div>

<script>
    const ctx = document.getElementById('chart');
    new Chart(ctx, { /* ... */ });
</script>
```

### 요청 가로채기 (Interceptor, v4)

```blade
<script>
    this.$intercept('save', ({ onSuccess, onError }) => {
        onSuccess(({ payload }) => {
            console.log('저장 성공');
        });

        onError(() => {
            alert('저장 실패');
        });
    })
</script>
```

전역:

```js
Livewire.interceptMessage(({ component, onSuccess, onError, onFailure }) => {
    onFailure(() => {
        alert('네트워크 오류가 발생했습니다.');
    });
});
```

> **v3 대비**: v3의 `Livewire.hook('commit', ...)`, `Livewire.hook('request', ...)`는 v4에서 `interceptMessage` / `interceptRequest`로 대체되었습니다. 구 API도 호환은 됩니다.

### `wire:stream` — 실시간 스트리밍

LLM 응답처럼 조금씩 흘려보내야 할 때 씁니다.

```php
public function ask()
{
    foreach ($this->llmStream() as $chunk) {
        $this->stream($chunk, el: '#answer');   // v4 시그니처
    }
}
```

```blade
<div wire:stream="answer" id="answer"></div>
```

> **v3 대비**
> ```php
> // v3
> $this->stream(to: '#answer', content: $chunk, replace: false);
> // v4
> $this->stream($chunk, el: '#answer');
> ```

## 20. v4 신기능: Islands, Defer, Async

### Islands — 컴포넌트 안의 독립 영역

컴포넌트를 쪼개지 않고도 일부만 독립적으로 갱신할 수 있습니다.

```php
<?php
use Livewire\Component;
use Livewire\Attributes\Computed;

new class extends Component {
    public string $search = '';

    #[Computed]
    public function expensiveStats()
    {
        return Order::selectRaw('SUM(total) as revenue, COUNT(*) as cnt')->first();
    }
};
?>

<div>
    <input wire:model.live="search">

    {{-- 이 안쪽은 별도로 갱신됨. search 변경 시 재계산되지 않음 --}}
    @island(name: 'stats', lazy: true)
        <div class="grid grid-cols-2 gap-4">
            <div>매출: {{ $this->expensiveStats->revenue }}</div>
            <div>건수: {{ $this->expensiveStats->cnt }}</div>
        </div>
    @endisland

    @foreach ($this->results as $r) ... @endforeach
</div>
```

Island만 갱신하기:

```blade
<button wire:click="loadMore" wire:island.append="stats">더 보기</button>
```

**언제 쓰나**: 무거운 통계 위젯, 사이드바, 알림 카운터처럼 "페이지 일부인데 갱신 주기가 다른" 것들. 자식 컴포넌트를 만드는 것보다 가볍습니다.

### Lazy / Defer — 지연 로딩

```blade
{{-- 화면에 보일 때 로드 --}}
<livewire:revenue-chart lazy />

{{-- 초기 페이지 로드 직후 로드 --}}
<livewire:revenue-chart defer />

{{-- 여러 개를 묶어서 한 요청으로 --}}
<livewire:revenue lazy.bundle />
<livewire:expenses lazy.bundle />
```

```php
use Livewire\Attributes\{Lazy, Defer};

#[Lazy]
class RevenueChart extends Component { }

#[Lazy(bundle: true)]
class RevenueChart extends Component { }

#[Defer]
class Revenue extends Component { }
```

플레이스홀더 지정:

```blade
@placeholder
<div class="h-64 bg-gray-100 animate-pulse rounded"></div>
@endplaceholder

<div>
    {{-- 실제 내용 --}}
</div>
```

## 21. 테스트

Livewire는 테스트가 편한 편입니다. 브라우저 없이 컴포넌트 동작을 그대로 검증할 수 있습니다.

```php
use Livewire\Livewire;
use App\Models\{Post, User};

it('게시글을 생성한다', function () {
    $user = User::factory()->create();

    Livewire::actingAs($user)
        ->test('post.create')
        ->set('title', '테스트 제목')
        ->set('content', '본문 내용입니다. 충분히 길게.')
        ->call('save')
        ->assertHasNoErrors()
        ->assertRedirect('/posts');

    expect(Post::where('title', '테스트 제목')->exists())->toBeTrue();
});

it('제목이 없으면 검증에 실패한다', function () {
    Livewire::test('post.create')
        ->set('title', '')
        ->call('save')
        ->assertHasErrors(['title' => 'required']);
});

it('검색이 동작한다', function () {
    Post::factory()->create(['title' => 'Laravel 입문']);
    Post::factory()->create(['title' => 'Python 입문']);

    Livewire::test('post.index')
        ->set('search', 'Laravel')
        ->assertSee('Laravel 입문')
        ->assertDontSee('Python 입문');
});
```

## 22. 자주 겪는 함정 모음

### 1. 루트 엘리먼트가 없거나 둘 이상

```blade
{{-- ❌ 아무것도 안 보이거나 이상하게 동작 --}}
<h1>제목</h1>
<p>내용</p>

{{-- ✅ --}}
<div>
    <h1>제목</h1>
    <p>내용</p>
</div>
```

### 2. `@if`로 루트를 감싸기

```blade
{{-- ❌ 조건이 거짓이면 루트가 사라져 컴포넌트가 죽음 --}}
@if ($show)
    <div>...</div>
@endif

{{-- ✅ --}}
<div>
    @if ($show)
        ...
    @endif
</div>
```

### 3. 반복문에 `wire:key` 누락

증상: 삭제했는데 다른 항목이 사라진 것처럼 보임, input 값이 뒤섞임.

```blade
@foreach ($items as $item)
    <div wire:key="item-{{ $item->id }}">...</div>
@endforeach
```

### 4. public 프로퍼티에 큰 컬렉션 담기

```php
// ❌ 게시글 100건이 매 요청마다 왕복
public Collection $posts;

// ✅
#[Computed]
public function posts() { return Post::all(); }
```

### 5. `private`/`protected` 프로퍼티가 사라짐

```php
// ❌ mount()에서 세팅해도 다음 요청에서 null
protected $service;
public function mount() { $this->service = app(Service::class); }

// ✅ boot()에서 매 요청 세팅
public function boot() { $this->service = app(Service::class); }
```

### 6. 모델의 관계가 사라짐

```php
// ❌
public function mount(Post $post) { $this->post = $post->load('comments'); }

// ✅
#[Computed]
public function comments() { return $this->post->comments()->get(); }
```

### 7. `wire:model` 기본값이 지연이라는 걸 모름

```blade
{{-- 타이핑해도 서버로 안 감. 실시간을 원하면 --}}
<input wire:model.live.debounce.300ms="search">
```

### 8. 액션 파라미터를 신뢰

```php
// ❌
public function delete(int $id) { Post::find($id)->delete(); }

// ✅
public function delete(Post $post)
{
    $this->authorize('delete', $post);
    $post->delete();
}
```

### 9. 배열에서 `unset()` 후 `array_values()` 누락

```php
unset($this->items[$i]);
$this->items = array_values($this->items);   // 필수
```

### 10. 서드파티 JS가 깨짐

```blade
<div wire:ignore>
    <select id="select2">...</select>
</div>
```

### 11. `wire:navigate` 사용 시 스크립트 재실행 안 됨

```js
// ❌
document.addEventListener('DOMContentLoaded', init);

// ✅
document.addEventListener('livewire:navigated', init);
```

### 12. 예약어 메서드명 사용

`reset`, `mount`, `render`, `validate`, `dispatch`, `fill`, `all`, `boot` 등은 피하세요.

### 13. 페이지 하나에 페이지네이션이 둘

```php
Post::paginate(10, pageName: 'postsPage');
Comment::paginate(10, pageName: 'commentsPage');
```

### 14. v4 컴포넌트 태그를 안 닫음

```blade
<livewire:counter />   {{-- ✅ --}}
<livewire:counter>     {{-- ❌ v4에서는 뒤 내용이 slot으로 해석됨 --}}
```

### 15. `/livewire/` 경로 하드코딩

v4부터 엔드포인트가 `/livewire-{hash}/`로 바뀌었습니다. 방화벽 규칙, CDN 설정, 미들웨어에 `/livewire/`를 하드코딩했다면 수정이 필요합니다.

## 23. 실습: Todo 앱 전체 코드

배운 내용을 한 번에 확인할 수 있는 예제입니다.

### 마이그레이션

```php
Schema::create('todos', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('title');
    $table->boolean('completed')->default(false);
    $table->unsignedInteger('position')->default(0);
    $table->timestamps();
});
```

### 모델

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Todo extends Model
{
    protected $fillable = ['user_id', 'title', 'completed', 'position'];

    protected $casts = ['completed' => 'boolean'];

    public function scopeOwned($query)
    {
        return $query->where('user_id', auth()->id());
    }
}
```

### Form 객체

```php
<?php
// app/Livewire/Forms/TodoForm.php

namespace App\Livewire\Forms;

use App\Models\Todo;
use Livewire\Attributes\Validate;
use Livewire\Form;

class TodoForm extends Form
{
    public ?Todo $todo = null;

    #[Validate('required|string|min:2|max:255', message: '할 일을 2자 이상 입력해 주세요.')]
    public string $title = '';

    public function setTodo(Todo $todo): void
    {
        $this->todo  = $todo;
        $this->title = $todo->title;
    }

    public function store(): Todo
    {
        $this->validate();

        $todo = Todo::create([
            'user_id'  => auth()->id(),
            'title'    => $this->title,
            'position' => Todo::owned()->max('position') + 1,
        ]);

        $this->reset();

        return $todo;
    }

    public function update(): Todo
    {
        $this->validate();

        $this->todo->update(['title' => $this->title]);

        return $this->todo;
    }
}
```

### 컴포넌트

```bash
php artisan make:livewire pages::todo.index
```

```php
<?php
// resources/views/pages/todo/⚡index.blade.php

use App\Livewire\Forms\TodoForm;
use App\Models\Todo;
use Livewire\Component;
use Livewire\Attributes\{Computed, Layout, Locked, Title, Url};

#[Layout('layouts::app')]
#[Title('할 일 목록')]
new class extends Component {
    public TodoForm $form;

    #[Url(except: '')]
    public string $search = '';

    #[Url(except: 'all', history: true)]
    public string $filter = 'all';   // all | active | completed

    #[Locked]
    public ?int $editingId = null;

    // ------------------------------------------------------------
    // 조회
    // ------------------------------------------------------------

    #[Computed]
    public function todos()
    {
        return Todo::owned()
            ->when($this->search, fn ($q) =>
                $q->where('title', 'like', "%{$this->search}%"))
            ->when($this->filter === 'active', fn ($q) =>
                $q->where('completed', false))
            ->when($this->filter === 'completed', fn ($q) =>
                $q->where('completed', true))
            ->orderBy('position')
            ->get();
    }

    #[Computed]
    public function remainingCount(): int
    {
        return Todo::owned()->where('completed', false)->count();
    }

    // ------------------------------------------------------------
    // 액션
    // ------------------------------------------------------------

    public function save()
    {
        $this->editingId
            ? $this->form->update()
            : $this->form->store();

        $this->cancelEdit();
        $this->refreshList();
    }

    public function toggle(Todo $todo)
    {
        $this->authorize('update', $todo);

        $todo->update(['completed' => ! $todo->completed]);

        $this->refreshList();
    }

    public function edit(Todo $todo)
    {
        $this->authorize('update', $todo);

        $this->editingId = $todo->id;
        $this->form->setTodo($todo);
    }

    public function cancelEdit()
    {
        $this->editingId = null;
        $this->form->reset();
        $this->resetValidation();
    }

    public function delete(Todo $todo)
    {
        $this->authorize('delete', $todo);

        $todo->delete();

        $this->refreshList();
    }

    public function clearCompleted()
    {
        Todo::owned()->where('completed', true)->delete();

        $this->refreshList();
    }

    public function updateOrder(array $order)
    {
        foreach ($order as $position => $id) {
            Todo::owned()->where('id', $id)->update(['position' => $position]);
        }

        $this->refreshList();
    }

    private function refreshList(): void
    {
        unset($this->todos, $this->remainingCount);
    }
};

?>
```

## 24. NativePHP 관점에서 중요한 것

### 현재 상황 (2026년 8월 기준)

- **NativePHP for Mobile v3** (stable): 웹뷰 기반. Blade/Livewire/React/Vue 모두 사용 가능. Livewire 4의 ⚡ 이모지 파일명 처리 이슈도 해결되었습니다.
- **NativePHP for Mobile v4** (beta): **SuperNative** 아키텍처 도입. 웹뷰를 제거하고 **EDGE 컴포넌트**(Blade 태그 → SwiftUI/Jetpack Compose 네이티브 뷰)로 렌더링합니다. 웹뷰는 여전히 하나의 컴포넌트로 사용 가능해서 화면 단위로 점진 이전할 수 있습니다.

> v4의 EDGE는 "Livewire처럼 느껴지도록" 설계되었습니다. `Route::native()`로 화면을 등록하고 PHP 컴포넌트 클래스가 화면을 구동하는 방식입니다. **즉, Livewire를 배워두면 v3 웹뷰 방식에도, v4 EDGE 방식에도 그대로 사고방식이 이어집니다.** 시간 투자가 헛되지 않습니다.

### 학습 우선순위 재조정

이전 세션에서 "Components / Properties / Actions / Forms 4개 챕터"를 권했던 이유는 NativePHP 컴포넌트 문법의 뼈대가 이 4개이기 때문입니다. 이 문서 기준으로는:

**필수 (여기까지가 90%)**
- 2장 동작 원리 — 특히 "상태가 왕복한다"는 감각
- 3~4장 컴포넌트
- 5장 Properties + `wire:model`
- 6장 Actions
- 7장 Forms

**바로 뒤따라 필요한 것**
- 8장 Lifecycle (`mount`, `updated`)
- 9장 Computed
- 10장 `wire:key` — 리스트를 만들면 무조건 만납니다
- 11장 Loading States

**모바일에서 특히 유용**
- 12장 Events — 네이티브 이벤트(카메라 결과, 생체 인증 결과 등)를 Livewire 컴포넌트로 받을 때 씁니다
- 18장 Alpine — 터치 반응처럼 즉각적이어야 하는 것들
- 20장 Islands / Lazy — 저사양 기기에서 초기 렌더링 부담을 줄일 때

**당장은 불필요**
- 14장 Pagination (모바일에서는 무한 스크롤이 더 흔함)
- 16장 URL Query (모바일 앱에 URL 개념이 약함)
- 17장 `wire:navigate` (v3 웹뷰에서는 유용, v4 EDGE에서는 네이티브 내비게이션 사용)

### 모바일 환경에서 추가로 신경 쓸 것

1. **snapshot 크기**: 저사양 기기에서는 JSON 직렬화/파싱 비용이 데스크톱보다 체감됩니다. public 프로퍼티를 최소화하세요.
2. **로컬 SQLite**: 기기 안에서 도는 앱이므로 DB도 로컬입니다. N+1 쿼리가 네트워크 없이도 느려질 수 있습니다.
3. **오프라인 우선**: 서버 API를 호출하는 부분은 실패를 전제로 설계해야 합니다. `wire:offline`과 큐를 조합하세요.
4. **터치 지연**: 버튼 탭 → 서버 왕복 → 화면 갱신 사이의 수십 ms도 모바일에서는 느껴집니다. 가능한 것은 Alpine으로 낙관적 UI(optimistic UI)를 먼저 그리고, 서버 응답으로 확정하는 패턴을 쓰세요.

```blade
{{-- 낙관적 UI 예시 --}}
<div x-data="{ done: @js($todo->completed) }">
    <input type="checkbox"
           x-model="done"
           @change="$wire.toggle({{ $todo->id }})">
    <span :class="done && 'line-through'">{{ $todo->title }}</span>
</div>
```

### v3 → v4 주요 변경 요약

| 항목 | v3 | v4 |
|---|---|---|
| 기본 컴포넌트 형식 | class-based | SFC (⚡ 파일) |
| 라우팅 | `Route::get('/x', X::class)` | `Route::livewire('/x', 'x')` |
| 컴포넌트 태그 | 닫지 않아도 됨 | **반드시 닫아야 함** |
| `wire:model.blur` | 네트워크 타이밍만 | 클라이언트 동기화도 제어 |
| `wire:transition` | Alpine x-transition | View Transitions API (수식어 제거) |
| `wire:scroll` | 스크롤 보존 | `wire:navigate:scroll` |
| 엔드포인트 | `/livewire/update` | `/livewire-{hash}/update` |
| JS 액션 | `$js('name', fn)` | `this.$js.name = fn` |
| JS 훅 | `Livewire.hook('commit')` | `Livewire.interceptMessage()` |
| 스트리밍 | `stream(to:, content:)` | `stream($content, el:)` |
| Volt | 별도 패키지 | Livewire 내장 SFC로 흡수 |
| 레이아웃 설정 | `'layout' => 'components.layouts.app'` | `'component_layout' => 'layouts::app'` |
