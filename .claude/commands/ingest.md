# Ingest

새 소스를 위키에 흡수한다. `sources/` 디렉토리에 추가된 파일이나 URL, 텍스트를 읽고 관련 위키 페이지를 생성하거나 갱신한다.

## 사용법

```
/ingest [파일경로 | URL | "텍스트 내용"]
```

인자 없이 실행하면 `sources/` 디렉토리에서 아직 처리되지 않은 파일을 자동 감지한다.

## 실행 절차

다음 단계를 순서대로 수행한다.

**1단계 — 소스 파악**

인자가 주어진 경우:
- 파일 경로이면 해당 파일을 읽는다
- URL이면 WebFetch로 내용을 가져온다
- 텍스트이면 그대로 사용한다

인자 없이 실행된 경우:
- `sources/` 디렉토리를 스캔하여 `log.md`에 `[INGEST]` 항목이 없는 파일을 찾는다

**2단계 — 내용 분석**

소스를 읽고 다음을 파악한다:
- 이 소스가 다루는 DDD/Laravel 개념은 무엇인가?
- 기존 위키 페이지(`index.md` 참조) 중 갱신이 필요한 페이지는 어디인가?
- 새로 생성해야 할 페이지는 무엇인가?

**3단계 — 위키 페이지 갱신 / 생성**

- 기존 페이지가 있으면: 새로운 정보를 해당 섹션에 추가하거나 기존 내용을 보완한다. 기존 내용을 삭제하지 말 것.
- 새 페이지가 필요하면: `schema.md`의 페이지 형식을 따라 생성한다. 위치는 카테고리에 맞는 `wiki/` 하위 디렉토리.
- 페이지 간 `[[링크]]`를 연결한다.
- 10–15개 페이지를 목표로 한다.

**4단계 — index.md 업데이트**

새로 생성된 페이지를 `index.md`의 적절한 카테고리 테이블에 추가하고 통계(전체 페이지 수, 최종 업데이트)를 갱신한다.

**5단계 — log.md 기록**

`log.md` 맨 위에 다음 형식으로 추가한다:
```
[YYYY-MM-DD] [INGEST] 소스명 — 생성/갱신된 페이지: PageA, PageB, ...
```

**6단계 — 처리 완료 보고**

다음을 요약하여 보고한다:
- 처리된 소스
- 새로 생성된 페이지 목록
- 갱신된 페이지 목록
- 추가 권장 작업 (관련 개념 중 아직 위키 페이지가 없는 것)
